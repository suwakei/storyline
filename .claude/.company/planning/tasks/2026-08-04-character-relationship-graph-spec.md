## 概要

社長依頼「キャラクター相関図を GUI で作れるようにする」の**何を作るか**を確定させる。
storyline は「シナリオの時系列と**キャラクターのつながり**を整理するツール」を名乗りながら、
つながりを図にする機能が無い（現状は `Character.color` のコメントに「相関図で使う識別色」と
書かれているだけ）。プロダクトの看板の半分が未実装のまま。ここを埋める。

**このチケットが後続 3 件のゲート**。spec が確定しないと design も dev も着手できない。

   **「参照ビジュアル」節**。社長提示のスクリーンショットは**親オーケストレータしか見ていない**。

## 決めること（下記 6 論点。**結論か「v1 スコープ外＋理由」のどちらかを必ず出す**）

1. **関係（エッジ）が持つ属性** — ラベル、向き（単方向 / 双方向 / 無向）、線種や色、強度など
2. **ノード座標の持ち方** — 手動配置して保存するのか、自動レイアウトなのか
   （手動なら `Character` に x/y を持たせるか、別の Layout データを持つことになる）
3. **相関の粒度** — 作品につき 1 枚か、ストーリーごとか、時点ごとに変化させるのか
4. **既存 `Scene.characterIds` との関係** — 共演から自動で線を引くか、完全に手動か
5. **配置場所** — どの画面に置くか（ドロワー / タブ / 専用ルート）、**スマホ幅でどう見せるか**
6. **書き出し JSON への含め方** と、既存 JSON（相関データ無し）の読み込み互換

### スコープの制約（社長確定・動かさない）

- ノードになるのは **キャラクター ＋ グループ枠**（陣営・組織・家族）のみ。
  **シーンや場所はノードにしない**（今回のスコープ外）。
- **実装方式（React Flow か自前 SVG か）はこのチケットで決めない**。dev / design への委任事項。
  spec は「何が必要か」を書き、「どう作るか」は書かない。

### 前提として効いている既存決定

- **モバイルファースト**。PC とスマホで仕様が競合したら**スマホを優先**する
  （[accounts-and-server 決裁記録](../../secretary/decisions/2026-08-04-accounts-and-server-decisions.md) の差分 1）。
  相関図は本来 PC の広い画面向きの機能なので、**ここが最大の緊張点**になる。
- 進行中の `accounts-and-server`（サーバ移行）とデータモデルで干渉する（干渉点 I-1 / I-2）。
  **どちらの土台に載せるかの進行順は秘書決裁 R-1 で「ローカル版に先に載せる」が既定**。
  spec 側でこれを覆す必要があるなら理由を書いて差し戻すこと。

## 決定サマリ（詳細は本稿ファイル）

| # | 論点 | 決定 |
| --- | --- | --- |
| 1 | エッジの属性 | **ラベル（自由テキスト）＋ 向き（`forward` / `both` / `none`）だけ**。線種・色・強度は v1 スコープ外（凡例が必要になり 375px の面積を食うため）。双方向は 2 本にせず 1 本 + 属性で表す。自己ループ禁止 |
| 2 | ノード座標 | **手動配置して保存。ただし保存されるのはユーザが動かしたノードだけ**。未配置は決定的な既定位置に置き書き込まない（**開いただけで `updatedAt` が進み一覧の並びが変わるのを防ぐ**）。ズーム倍率・パン位置は保存しない。置き場所（`Character` 直下か別型か）は dev 判断 |
| 3 | 相関の粒度 | **作品につき 1 枚**。ストーリー別・時点別にしない（時点別は「実日付を持たない」設計を崩す。並べ替えで相関の意味が変わってしまう） |
| 4 | `Scene.characterIds` | **完全に手動。共演から自動で線を引かない**（共演 ≠ 関係／一望性が壊れる／「消した」状態の保存が要る）。相関図はシーンのデータを一切変えない |
| 5 | 配置場所 | **作品画面のメイン領域を「構成 ↔ 相関図」で切替**。新ルートもドロワーも使わない（画面遷移は 2 つだけの原則・`Drawer` は 448px で狭い）。キャラ本体の編集は既存 `CharacterPanel` に一本化 |
| 6 | 書き出し JSON | `Project` の一部として同梱。**`EXPORT_FORMAT` / `EXPORT_VERSION = 1` は据え置き**（追加のみで既存の意味を変えないため）。旧 JSON は「相関データが無い作品」として読む。壊れた参照は捨てる |
| — | グループ枠 | **単層（入れ子なし）。1 キャラは最大 1 グループ**。枠の位置・大きさは**メンバーの外接矩形から自動算出**し、データとして持たない |
| — | 375px | **閲覧も編集も可。ドラッグ結線を必須経路にしない**（タップ 2 段階を用意）。全体表示（構造を見る）＋ フォーカス表示（1 人の近傍だけ読む）の 2 段構え。関係リストを v1 に含める |
| — | 進行順 | 秘書決裁 **R-1 の既定 (a)「ローカル版に先に載せる」を追認**（覆さない） |

### データモデルに要求するもの（詳細は本稿 10 章）

- 新規 `Relationship` = `id` / `fromId` / `toId` / `label` / `direction`（すべて必須）
- 新規 `CharacterGroup` = `id` / `name`（すべて必須）
- `Character` に `x?` / `y?` / `groupId?`（すべて任意）
- `Project` に `relationships` / `characterGroups`（読み込み時に無ければ空配列）
- **持たないもの**: エッジの線種・色・強度／グループの色・座標・サイズ・親／ズーム倍率・パン位置・
  表示モード／キャラクター画像／日付フィールド
