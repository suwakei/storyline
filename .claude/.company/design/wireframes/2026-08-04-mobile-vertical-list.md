- 前提: **375px 幅（iPhone SE / iPhone 14 相当）を基準に描く**（`md`=768px 未満はすべてこの

テキスト図はいずれも等幅フォント想定。実寸ではなく構造・情報の優先順位を示すもの。

## A. 画面全体（ヘッダ〜縦リスト、375px 基準）

```
┌───────────────────────────────────────┐ 0px
│ ← 一覧   作品タイトル                   │ ← ヘッダ (flex-wrap、既存のまま)
│                    [👤 3] [書き出す]    │   幅が足りないと自然に折り返す
│ ログライン・メモ…                        │
├───────────────────────────────────────┤
│ [第一幕 12] [第二幕 8] [+ ストーリー] →  │ ← StoryTabs (既存のまま、横スクロール)
├───────────────────────────────────────┤
│                                         │
│   すべて折りたたむ                      │ ← 新規: 目次モードとの切替トグル
│                                         │
│ ▾ 第一幕            5件  [▲][▼][✕]     │ ← シークエンス見出し (展開中)
│   物語の導入をどう見せるか               │
│  ┌────────────────────────────────┐   │
│  │ ┌────┐ S1 事件発生          [▲] │   │ ← シーン行 (詳細は B)
│  │ │thumb│ 深夜／旧校舎 3F          │   │
│  │ │64x64│ ●田中 ●鈴木          [▼] │   │
│  │ └────┘           [プロット]     │   │
│  └────────────────────────────────┘   │
│  ┌────────────────────────────────┐   │
│  │ ┌────┐ S2 目撃者への聞き込み [▲] │   │
│  │ │    │ 早朝／駅前                │   │
│  │ │    │ ●田中               [▼] │   │
│  │ └────┘           [執筆中]       │   │
│  └────────────────────────────────┘   │
│   （以下 S3〜S5 続く）                  │
│  [ ＋ シーンを追加                  ]  │ ← 横幅いっぱいのボタン (高さ44px以上)
│                                         │
│ ▸ 第二幕            8件                │ ← シークエンス見出し (折りたたみ中)
│   （タップで展開。▲▼✕ は非表示）        │
│                                         │
│ [ ＋ シークエンスを追加             ]  │
│                                         │
└───────────────────────────────────────┘
  ↑ この列全体が overflow-y-auto (flex-1 min-h-0)。
    Board.tsx の横スクロール同様、ここが縦スクロールの唯一の場所になるよう
    親要素の flex 構造を崩さないこと（崩すと横スクロール漏れと同じ事故が縦で起きる）
```

- 「すべて折りたたむ」は状態に応じて「すべて開く」に文言が反転する
  （1つでも展開中なら「すべて折りたたむ」、全部畳まれていれば「すべて開く」）
- 見出し・シーン行のインデントは表現上のもので、実装は左端揃え + 内側パディングで良い
  （枠線で階層を示すのは既存の `SequenceColumn` の「1 枠 = 1 シークエンス」表現を踏襲する
  意図。厳密な入れ子構造を要求するものではない）
- 頻度の高い操作（シーンを開く／並べ替える）はスクロール位置＝今見ている場所にそのまま
  存在するため、片手操作でも指を大きく動かさずに届く
  （[ui-spec](../ui-specs/2026-08-04-mobile-vertical-list.md) 決定6）
- ヘッダの `[👤 3] [書き出す]` とストーリータブの並べ替え/削除アイコンは、`md` 未満では
  44×44 相当までタップ領域を拡張する（見た目の枠は現状のままでも、当たり判定だけ広げれば
  よい）。`md` 以上では現状のサイズに戻す（ui-spec 決定6・8）

## B. シーン行の拡大図（1件分、375px 基準）

```
┌──────────────────────────────────────────┐
│ ┌──────┐ S12  旧校舎で遺体発見           │┌───┐
│ │      │  ─────────────────────         ││ ▲ │ 44×44
│ │ thumb│  深夜 ／ 旧校舎 3F              │└───┘
│ │ 64×64│  ●田中 ●鈴木 +1                │┌───┐
│ │      │                     [プロット] ││ ▼ │ 44×44
│ └──────┘                                │└───┘
└──────────────────────────────────────────┘
 ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^  ^^^^^
 ここ全体が 1 個の <button> (タップでシーン編集    ▲▼ は独立した IconButton
 ドロワーを開く)。role="button" の入れ子にしない   (兄弟要素。行全体を role="button"
 ため、行の親要素は plain <div>                    にはしない)
```

- サムネイル 64×64: `thumbnail` が無いシーンでも同じ枠を確保し、行の高さを揃える
  （高さが不揃いだと一望性が落ちる — 既存の `06-ui-design.md` §3 の原則をそのまま適用）
- 1行目: `S` 番号（`tabular-nums`、`text-muted`）+ タイトル（`truncate`）
- 2行目: 時間 ／ 場所（`truncate`、両方空なら行ごと非表示。高さは thumbnail 側が決めるので
  崩れない）
- 3行目: 登場キャラクター。**カンバンと同じ「色ドット + 名前」を維持する**（色ドットだけを
  やめてテキストのみにはしない）。識別色は「誰が出ているか」を一瞬で見分ける核心情報で、
  storyline の価値である「キャラクターのつながりの一望性」に直結するため、幅の都合で削る
  対象にはしない。幅の制約は表示件数（カンバンの最大4件→**最大3件+N**）と折り返し禁止
  （`flex-nowrap`）で吸収する
- ステータスバッジ: 右下寄せ。既存 `SCENE_STATUSES[].className` をそのまま使う
  （ラベル文字も出すので色だけに頼らない）
- ▲ / ▼: 行の右端に縦積み。行の高さがサムネイル (64px) だけでなく `▲(44)+▼(44)=88px` にも
  従うため、行全体は概ね 88px 前後になる（カンバンの 1 カード 150〜220px と比べれば、
  依然として大幅にコンパクト）

## C. シークエンス見出しの拡大図（375px 基準）

```
展開時:
┌──────────────────────────────────────────┐
│[▾] シークエンス名（編集可）  5件 [▲][▼][✕]│
│    このシークエンスの狙い（編集可・小文字）  │
└──────────────────────────────────────────┘
 44×44  InlineText, flex-1         各44×44

折りたたみ時:
┌──────────────────────────────────────────┐
│[▸] シークエンス名（編集可）        5件     │
└──────────────────────────────────────────┘
 44×44  InlineText, flex-1
```

- `[▾]/[▸]` は独立した `IconButton`（`aria-expanded` 付き）。折りたたみ状態の唯一のトリガー
- タイトル (`InlineText`) は chevron ボタンの**外側の兄弟要素**。`<button>` の中に
  `<input>` を入れない（HTML 上不正・入れ子インタラクティブの回避）
- 折りたたみ時は `▲ / ▼ / ✕` を非表示にして、目次的な軽さを優先する
  （「情報を増やすなら何を削るか」の実践。展開すれば全部出てくる）

## D. シーン編集ドロワー（決定5: 所属シークエンスの追加、375px 基準）

```
┌───────────────────────────────────┐
│ シーン編集  第一幕            [✕] │ ← 既存 Drawer ヘッダ
├───────────────────────────────────┤
│ タイトル                           │
│ [___________________________]     │
│                                     │
│ 時間ラベル        場所             │
│ [____________]   [____________]   │
│                                     │
│ ステータス                         │
│ [プロット][執筆中][完了]           │
│                                     │
│ 所属シークエンス          ← 新規  │
│ [ 第二幕へ移動            ▾ ]      │ ← <select>, min-h-11
│  （現在のシークエンスは選択肢から除外。│
│    シークエンスが1つの作品では非表示） │
│                                     │
│ あらすじ                           │
│ [___________________________]     │
│  …(既存フィールドはそのまま)…       │
├───────────────────────────────────┤
│ [削除]          [複製] [閉じる]    │ ← 既存 Drawer フッター（タップ領域のみ44に拡張）
└───────────────────────────────────┘
```

- 挿入位置は「ステータス」の直後を推奨（シーンの分類に関わる項目同士でまとまる）。
  最終的な並びは開発部の裁量
- 選択すると即座に `moveScene(projectId, storyId, sceneId, 選んだ sequenceId, 十分大きい index)`
  を呼び、末尾に追加する（保存ボタンを押させない、他フィールドと同じ「選んだら即反映」の
  操作感に揃える）
- 375px 幅では `Drawer` は実質フルスクリーン表示になるため、レイアウト崩れは無い
  （`w-full max-w-md` が既にそのように振る舞う）

## E. PC 幅（`md` = 768px 以上）との差分

375px 基準で決めた内容のうち、PC 幅で**変わるもの**と**変わらないもの**を明記する
（[ui-spec](../ui-specs/2026-08-04-mobile-vertical-list.md) 決定7: 競合時はスマホ優先）。

| 画面要素 | 375px（縦リスト、本仕様の基準） | `md` 以上（PC カンバン） | 差分 |
| --- | --- | --- | --- |
| シーン・シークエンスの並び | A〜C の縦アコーディオン + ▲/▼ ボタン | 既存 [Board.tsx](../../../../src/components/board/Board.tsx) / [SequenceColumn.tsx](../../../../src/components/board/SequenceColumn.tsx) の横スクロールカンバン + dnd-kit ドラッグ | **変わる**。両方の DOM を CSS (`hidden md:block` / `md:hidden`) で出し分け、PC 側の実装・見た目は一切変更しない |
| シーンカードの情報量 | B の簡略行（要約無し・キャラは色ドット+名前 最大3+N、`flex-nowrap`） | 既存 `SceneCardBody`（要約 `line-clamp-3`・キャラは色ドット+名前チップ 最大4+N、折り返しあり） | **一部変わる**。あらすじの有無・最大表示件数・折り返しの有無は画面ごとに異なるが、**色ドット付きで識別する点は両方で共通**（意味づけは統一。ui-spec §0） |
| タップ領域 | 全操作要素 44×44 以上 | 既存サイズのまま（28〜32px 相当） | **変わる**。`md:` で PC 側のサイズに戻すレスポンシブ上書き（ui-spec 決定6・8） |
| ヘッダ・StoryTabs の配置構造 | A のとおり（既存のまま） | 既存のまま（変更無し） | **変わらない** |
| シーン編集ドロワー内「所属シークエンス」(D) | 常時表示 | **常時表示（同じ実装）** | **変わらない**。決定5の理由のとおり、スマホ発の解決策を分岐させずに PC にもそのまま出す |
| Drawer / Modal の基本構造 | `w-full max-w-md` で実質フルスクリーン | `max-w-md` の右寄せパネル（既存のまま） | **変わらない**（既存の responsive 挙動のまま） |

- 表の「変わる」行が、このチケットで新規に作る部分（縦リスト本体・簡略行・タップ領域拡張）
- 「変わらない」行は今回の実装で触る必要が無いことの確認（既存挙動の維持を明記することで、
  実装時に PC 側を誤って変更しないようにする）
