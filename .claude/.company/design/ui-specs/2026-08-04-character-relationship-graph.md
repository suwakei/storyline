## 0. スコープと前提

- 対象: `/projects/[projectId]`（[page.tsx](../../../../src/app/projects/[projectId]/page.tsx)）に
  **新しく足すモード**「相関図」と、その中の全 UI
- 対象外: キャラクター本体（名前 / 立ち位置 / メモ / 識別色）の編集。既存
  [CharacterPanel](../../../../src/components/CharacterPanel.tsx) に一本化する（spec 5）。
  **相関図側に同じ入力欄を作らない**
- 対象外: 新ルート・ドロワー化（spec 5 が否定済み）、画像コピー / 印刷 / Undo / 自動レイアウト /
  複数選択（spec 14）
- **実装方式（React Flow / 自前 SVG / HTML オーバーレイ）を本稿では決めない**（秘書決裁 D-6）。
  代わりに [17 章](#17-dev-へ渡す-ui-要件リスト実装方式非依存) に方式を選ぶための要件リストを置く。
  本稿にライブラリ名前提の表現は 1 つも無い
- 基準幅は **375px**。PC はその展開（[mobile-vertical-list 決定 7](2026-08-04-mobile-vertical-list.md)
  と同じ優先順位）

### 本稿で使う寸法の単位

| 語 | 意味 |
| --- | --- |
| **論理 px** | 相関図の座標系（`Character.x` / `y` と同じ空間）。ズーム倍率を含まない |
| **スクリーン px** | 実際に画面上で占める大きさ。`論理 px × zoom` |

タップ領域の 44px は**常にスクリーン px**。

## 0-1. 参照ビジュアルをどう解釈したか（解釈が割れる箇所の明示）

参照ビジュアルは**文章の転記しか手がかりが無い**。以下は本稿の解釈であり、実物の画像とは
違いうる。**画像を見られる人（社長・親オーケストレータ）が違うと判断したら差し戻してよい。**

| 転記の記述 | 本稿の解釈 | なぜそう読んだか |
| --- | --- | --- |
| 「角丸の矩形ノード。ノード内は 1〜3 行のテキスト（太字の名前 + 補足行）」 | **角丸 8px（`rounded-lg` 相当）の矩形。名前（太字）＋ 立ち位置 の 2 行**。3 行目は作らない | spec 9 が「名前 ＋ 立ち位置 ＋ 識別色」に確定済み。角丸は既存カード（`rounded-lg` / `rounded-xl`）に合わせた |
| 「ノードを囲むグループ枠。枠の左上にグループ名ラベル」 | **枠の上辺に重なる `legend` 風のチップ**（枠線を切る形）。枠の内側左上に置く案は採らない | 枠の内側に置くと、枠が小さいとき（メンバー 1〜2 人）にラベルとノードが重なる。上辺に重ねれば枠がどれだけ小さくてもノードと衝突しない |
| 「ラベルは線の中央に小さな箱で乗る」 | **線分の中点に、線を隠す不透明な箱**（`bg-surface` + 1px `line` 枠 + 角丸 4px） | 「乗る」を「線より前面・不透明」と読んだ。半透明にすると線がラベル文字に重なって読めない |
| 「図の右上と右下に操作コントロールが浮いている」 | **右下のみ採用**。右上は置かない | 右上の 2 種（全画面 / コピー）が両方とも不採用のため（[5 章](#5-ビューポート操作コントロール-5-種の採否)）。空のコントロール群を置く意味が無い |
| 「背景は無地のダーク」 | **無地にせず、薄いドットグリッドを敷く**（意図的な逸脱） | 本アプリはライト / ダーク両対応。ライトモードではノード（`surface` = `#ffffff`）と背景（`bg` = `#f5f6f8`）のコントラストが **1.06:1** しかなく、無地だとノードが「面」として浮かない。ドットがノードに隠れることで面が認識できる（[15 章](#15-デザイントークンとコントラスト)） |
| 「図全体は本文カラムの中に収まり、キャンバスは横長」 | **横長を前提にしない**。キャンバスは画面の残り全部を占め、縦横比は端末に従う | 基準が 375px の縦画面。「本文カラムに収まる図」は GitHub の README 表示であって、編集画面の要件ではない |

## 1. 既存プリミティブの再利用可否（先に確認）

[ui.tsx](../../../../src/components/ui.tsx) を読んだ結果。

| プリミティブ | 相関図での用途 | 判定 |
| --- | --- | --- |
| `Button` / `IconButton`（`size="touch"` 込み） | ツールバー・ノードアクションバー・ズームコントロール・リスト内の各操作 | **そのまま使える**。`size="touch"` が 44px 要件をそのまま満たす |
| `Drawer` | 関係リスト・グループ管理 | **そのまま使える**。375px では実質フルスクリーン、PC では右 448px |
| `Modal` | 関係の編集（結線直後・ラベル箱タップ時）・グループ割り当て | **そのまま使える**（`role="dialog"` + `aria-modal` + Escape 済み） |
| `Field` / `TextInput` / `Select` | 関係の新規追加（誰から / 誰へ）、グループ選択 | **そのまま使える**。`Select` は `min-h-11` を明示（既存ルール） |
| `InlineText` | 関係ラベル・グループ名の編集 | **そのまま使える**。`CharacterPanel` と同じく枠付きクラスを付けて使う（保存ボタンを押させない） |
| `EmptyState` | キャラクター 0 人 | **そのまま使える** |

### 足りないもの（**1 つだけ**）

| 追加するもの | 置き場所 | 理由 |
| --- | --- | --- |
| `SegmentedControl` | [ui.tsx](../../../../src/components/ui.tsx) | 「構成 / 相関図」のモード切替と、関係の向き 3 択（`→` / `↔` / 線のみ）で**同じ見た目が 2 回**要る。加えて [SceneEditor](../../../../src/components/SceneEditor.tsx) のステータス 3 択が既に素の `<button>` 群で同じ形を手書きしている（**3 箇所目**）。ここで汎用化しておけば以後は増えない |

`SegmentedControl` の要件:

- `options: { value: string; label: string }[]` / `value` / `onChange(value)` / `size?: "md" \| "touch"`
- ラッパは `role="group"` + `aria-label`、各項目は `<button aria-pressed>`。
  **`role="tablist"` にはしない** — ロービングタブインデックスや矢印キー移動の実装義務が増える割に、
  ここでは Tab で順に辿れれば足りる
- 見た目: 選択中 = `bg-accent text-accentfg`、非選択 = `text-muted hover:bg-surface2 hover:text-fg`。
  外枠は `border-line rounded-md`、項目間は区切り線なし（選択中の面で区別する）
- **色だけで選択状態を伝えない**ため、選択中の項目は `font-semibold` も併用する
- SceneEditor のステータス 3 択の置き換えは**このチケットではやらない**（デグレのリスクを負わない）。
  別チケットで統合を検討する

**相関図本体は `ui.tsx` に入れない。** ストア（`useStore`）を直接読むため、
`src/components/graph/` 配下に置く（[CLAUDE.md](../../../../.claude/CLAUDE.md) のレイヤ分けに従う）。

## 2. 画面構成（モード切替）

**決定: ヘッダの直下に「構成 / 相関図」の `SegmentedControl` を 1 行置く。
相関図モードのときは [StoryTabs](../../../../src/components/StoryTabs.tsx) を DOM ごと出さない。**

```
ヘッダ（← 一覧 / 作品名 / キャラクター N / 書き出す / ログライン）  ← 既存のまま変更なし
─────────────────────────────────────────
[ 構成 ][ 相関図 ]                                  ← 新規。モード切替（44px 高 / md 以上は 32px）
─────────────────────────────────────────
「構成」  : StoryTabs + カンバン（md 以上）/ 縦リスト（md 未満）  ← 既存のまま
「相関図」: 相関図キャンバス（StoryTabs は出さない）
```

- **なぜタブより上位か**: spec 5 の決定どおり。ストーリータブは本編 / 外伝の切替で並べ替え・削除の
  対象だが、相関図は作品共通。同列に置くと「相関図タブを削除できるように見える」
- **StoryTabs は `hidden` ではなく描画しない**（相関図モード時）。`hidden` にすると Tab キーで
  到達できてしまう端末・実装があるため
- モードは**保存しない**。リロードで「構成」に戻る（spec 5）
- **相関図モードでは縦方向に StoryTabs の分（約 44px）だけ広い**。これが「全画面ボタンを採らない」
  判断の裏づけの一部（[5 章](#5-ビューポート操作コントロール-5-種の採否)）
- 375px でモード切替は**横幅いっぱいの 2 分割**、md 以上は**左寄せで内容幅**。
  `w-full md:w-auto` の CSS だけで出し分ける（JS の分岐を作らない）

### 相関図モードの縦の内訳（375×667 の場合）

| 帯 | 高さ |
| --- | --- |
| ヘッダ | 約 76px（既存） |
| モード切替 | 44px |
| キャンバスツールバー | 44px |
| **キャンバス** | **約 503px** |
| （選択中のみ）ノードアクションバーが下端に重なる | 88px |

## 3. キャンバスの構成要素

z 順（下から）: **① グループ枠 → ② エッジ線・矢じり → ③ ノード → ④ エッジのラベル箱 →
⑤ 選択 / ドラッグ中の装飾**。

> **なぜラベル箱がノードより前面か**: ラベルは関係の意味そのもので、隠れると図の意味が失われる。
> ノード名が隠れても、タップすればアクションバーに名前が出るので復元できる。

### 3-1. 背景

- 面は `bg-bg`（ページ背景と同じ）
- **ドットグリッド**: 論理 24px 間隔、半径 1 スクリーン px、色 `line`。ズームに追従して間隔が変わる
- ズーム 0.5 未満ではドットを描かない（密になりノイズになるため）
- ドットグリッドは**パンとズームが起きていることの唯一の手がかり**でもある（無地だと
  ノードが無い領域をパンしても動いて見えない）

### 3-2. ノード

**論理サイズ 160 × 60（固定）。全キャラクターが必ず 1 個ずつ出る（spec 9）。**

```
┌─────────────────────────────┐
│▌ 田中 太郎                   │  ← 名前  text-sm font-semibold text-fg  truncate
│▌ 主人公                      │  ← 立ち位置 text-[11px] text-muted     truncate
└─────────────────────────────┘
 ↑ 6px の識別色帯（左端・角丸に沿う）
```

| 要素 | 指定 |
| --- | --- |
| 面 | `bg-surface`（**不透明**。ドットグリッドを隠して「面」を作る） |
| 枠 | `border-line` 1px、角丸 8px（`rounded-lg`） |
| 識別色帯 | 左端 論理 6px。`style={{ background: character.color }}`（**データとしての色**の例外） |
| 名前 | `text-sm font-semibold text-fg`、1 行 `truncate`。空なら「名称未設定」を `text-muted` で |
| 立ち位置 | `text-[11px] text-muted`、1 行 `truncate`。**空なら行ごと出さない**（名前を縦中央に寄せる） |
| 内側余白 | 左 6（色帯）+ 8、右 10、上下 8 |
| 影 | 通常は無し。ドラッグ中のみ `shadow-lg` |

- `note`（メモ）は出さない、画像も持たない（spec 9）
- **ノード全体を識別色で塗らない**（通常表現では）。10 色は任意の色相で、白背景に置いたときの
  コントラストが 2:1 まで落ちるものがある（`#f59e0b` 等）。文字を載せると 4.5:1 を満たせない。
  帯にすれば「色で識別」と「文字が読める」を両立できる（[15 章](#15-デザイントークンとコントラスト)）

### 3-3. エッジ（関係）

**直線 1 本。ノード矩形の境界で両端をクリップする（中心同士を結んで矩形との交点で切る）。**

| 要素 | 指定 |
| --- | --- |
| 線 | 色 `muted`、太さ 論理 1.5px（スクリーン換算で **1〜2px にクランプ**） |
| 矢じり | `direction` に従う。`forward` = 終点側のみ / `both` = 両端 / `none` = 無し。塗り `muted`、論理 10px（スクリーン換算で **5〜10px にクランプ**） |
| 選択中 | 線を `accent`・太さ 2 倍、矢じりも `accent` |
| 曲線 | **使わない**（自動整形は spec 14 でスコープ外） |
| 同じ 2 人の間に複数本 | **法線方向に平行オフセット**。`i` 本目を `(i − (n−1)/2) × 論理 16px` ずらす。ラベル箱も一緒にずれるので重ならない |

**エッジの色をキャラクター識別色から導出しない。** 理由: 1 画面に「識別色」と「エッジの色」の
2 系統の色の意味が同居する。企画部がエッジに色属性を持たせなかったのと同じ判断軸
（spec 1）を表示側にも適用する。

#### ラベル箱

- 線分の**中点**に置く。`bg-surface`（不透明）+ `border-line` 1px + 角丸 4px + `px-1.5 py-0.5`
- 文字 `text-[11px] text-fg`、最大幅 論理 144px で `truncate`（全文は関係リストで読める）
- **ラベルが空文字なら箱を描かない**（空箱が並ぶと図が汚れる）
- **ズーム 0.6 未満では箱を描かない**（読めないうえに図を埋める。[4 章](#4-ズームと-2-段階の見え方-lod)）
- ラベル箱は**ズームに追従する**（サイズが線と釣り合わなくなるため）

### 3-4. グループ枠

**メンバーノードの外接矩形 + 論理 24px のパディングで毎回算出する。データには持たない（spec 7）。**

| 要素 | 指定 |
| --- | --- |
| 枠 | `border-muted` 1px 実線、角丸 12px（`rounded-xl` 相当） |
| 塗り | `bg-surface2/60` |
| ラベル | 枠の**上辺に重なるチップ**。左端から論理 12px の位置。`bg-bg` で枠線を切る。`px-1.5`、`text-[11px] font-medium text-fg` |
| 選択中 | 枠を `border-accent` 2px（どこまでが自分の枠か分かるように） |
| メンバー 0 | **図には描かない**（枠を算出できないため）。グループ管理ドロワーの一覧には「（メンバーなし・図には出ません）」と併記して出す |

- **枠線が `line` ではなく `muted` なのはコントラストのため**。`line`（`#dfe3e9`）を `bg`（`#f5f6f8`）の
  上に引くと **1.05:1** で事実上見えない。`muted` なら 4.4:1 で非テキスト要件（3:1）を確実に満たす
- 塗り（`surface2/60`）はライトモードでは弱いが、**ドットグリッドが枠の内側で隠れる**ため
  区画としては読める。ダークモードでは塗りもはっきり効く。**両モードで機能する担保は枠線とラベル**
- **描画順は面積の大きい枠から**（小さい枠が大きい枠の塗りに沈まないように）

#### 枠が重なったとき

- **禁止しない・自動で解消しない・警告も出さない。** 配置は作者の表現であり、勝手にノードを
  動かさない（spec 2 の「継続的な自動レイアウトは採らない」と同じ理由）
- 重なった部分は両方の枠線が見え、塗りが重なって濃くなる（**重なりが視覚的に分かる副作用**）
- 解消したい作者はノードを動かして分ける。その助けとして、グループ管理ドロワーで
  **グループを選ぶとその枠が `accent` でハイライトされる**

### 3-5. 未配置ノードの既定位置（デザイン部の推奨。最終判断は dev）

spec 2 の要件は「乱数を使わない / 重ならない / 配列順を根拠にしてよい」。

```
x = 40 + (index % 4) × 200
y = 40 + floor(index / 4) × 120      （index は Project.characters 配列上の位置）
```

- **列数を 4 で固定する**（`ceil(sqrt(n))` のように n 依存にしない）。n 依存だとキャラを 1 人足した
  瞬間に既存の未配置ノードが全部動く
- ピッチ 200 × 120 は、ノード 160 × 60 に対して横 40 / 縦 60 の間隔。**ズーム 0.6 でもスクリーン上で
  120 × 72px の間隔**があり、44px の当たり判定同士が重ならない（[8 章](#8-ノード移動とキャンバスパンの分離375px-の最大の緊張点)）
- **なぜ列数が少なめ（4）か**: 375px は縦長画面なので、図が縦に伸びる方が zoom-to-fit の倍率が
  上がる。30 人 = 4 列 × 8 行 → 論理 880 × 1020 → 375×503 の viewport に fit すると **約 0.43**。
  6 列にすると横に広がって約 0.29 まで落ちる

## 4. ズームと 2 段階の見え方（LOD）

**決定: ズーム 0.6 を境に、ノードの描き方を「通常表現」と「縮小表現」で切り替える。**

| | 通常表現（zoom ≥ 0.6） | 縮小表現（zoom < 0.6） |
| --- | --- | --- |
| ノード | `bg-surface` + `border-line` + 識別色帯 + 名前 + 立ち位置 | **識別色のベタ塗り** + `muted` 1px 輪郭。**テキストを描かない** |
| エッジのラベル箱 | 描く | **描かない** |
| 矢じり | 描く | 描く（クランプ下限 5px で潰れない） |
| グループ枠 | 描く | 描く |
| グループのラベル | 描く | 描く（**ズームに追従せず固定サイズ**） |
| ドットグリッド | 描く（0.5 以上） | 0.5 未満では描かない |
| ノードのドラッグ移動 | **できる** | **できない**（タップ選択のみ） |
| 結線（ドラッグ / タップ 2 段階） | **できる** | **できない** |

- **なぜ縮小表現でベタ塗りにするか**: 文字が読めない倍率では色が唯一の手がかりになる。
  面積を最大化する。文字を載せないのでコントラスト 4.5:1 の対象外になり、
  10 色すべてを安全に使える（[15 章](#15-デザイントークンとコントラスト)）
- **正直に書く**: `CHARACTER_COLORS` は 10 色の循環なので、**11 人目以降は色が重複する。
  縮小表示で個人を特定することはできない。** 縮小表示で読むのは「かたまりの位置と密度・枠・
  線が集中している場所」であり、spec 8 の「構造を見る（文字は読めなくてよい）」と一致する
- **グループのラベルだけズームに追従しない**のがこの設計の要。全体表示で唯一読めるテキストになり、
  「どの陣営がどこに固まっているか」が読める。枠幅がラベル幅より狭いときは `truncate`

### ズームの段と初期倍率

- ⊕ / ⊖ が移動する段: **0.3 / 0.5 / 0.75 / 1.0 / 1.5 / 2.0**（6 段）
- 初期倍率は**段にスナップせず連続の zoom-to-fit**（全ノードの外接矩形 + 余白 24px を収める）。
  **0.3〜1.0 にクランプ**（少人数のとき拡大しすぎない）
- PC（`Ctrl` / `⌘` + ホイール）とスマホ（ピンチ）は**連続ズーム**。0.3〜2.0 でクランプ
- **ズーム倍率・パン位置は保存しない**（spec 2）。開くたびに全体が収まる倍率から始まる

## 5. ビューポート操作コントロール 5 種の採否

参照ビジュアルにある 5 種すべてについて結論を出す。

| # | コントロール | 採否 | 理由 |
| --- | --- | --- | --- |
| 1 | **全画面（↔）** | **採らない** | 相関図はすでにメイン領域全体を占め、相関図モードでは StoryTabs（約 44px）も消えている。全画面化で増えるのはヘッダ + モード切替の約 120px だけで、代わりに「戻る手段が Escape しか無い」状態を作る。375px ではブラウザ UI の出入りと Fullscreen API の挙動が端末差で不安定になり、検証コストが割に合わない |
| 2 | **コピー（画像化）** | **採らない** | 企画部が v1 スコープ外と決定済み（spec 8 / 14）。デザイン部として追認する。図の画像化は 375px での出力サイズ・ライト / ダークどちらで出すかという別の設計課題を丸ごと連れてくる |
| 3 | **パン十字ボタン** | **採らない** | パンは「背景をドラッグ」で足り、ピンチと同居する。十字は 4 個 × 44px = 常時 88 × 88px を右下から奪う。右下は 375px で親指が最も届く一等地で、そこを最も低頻度の操作に使うのは誤り。**ただし十字が担っていた「ポインタ以外でのパン」は捨てない** → キャンバスにフォーカスがあるとき **矢印キーで論理 40px ずつパン**する（[16 章](#16-アクセシビリティ)） |
| 4 | **リセット（⟳）** | **採る**（`⟳ 全体表示` として） | パン・ズームで迷子になるのは実際に起きる。**加えてこのボタンは spec 8 の「全体表示 ↔ フォーカス表示をワンタップで往復する」の帰り道そのもの**なので、リセットとフォーカス解除を **1 個のボタンに統合する**。押すと「フォーカス解除 + 全体が収まる倍率と位置」に戻る |
| 5 | **ズーム（⊕ / ⊖）** | **採る** | ピンチが使えない環境（マウスのみの PC、支援技術）で必須。段を離散にしておくと「戻れなくなる」迷子が起きにくい |

### リセットのラベルに込める注意（spec 2 の要求）

**「リセット」はノードの配置を戻さない。** 文言でそれを伝える。

- `IconButton` の `label`（= `aria-label` + `title`）: **`"全体表示に戻す（ノードの配置は変わりません）"`**
- ボタン面に出す記号: `⟳`
- 「配置をリセットして並べ直す」機能は v1 では作らない（spec 2 / 14）

### 浮遊コントロールの配置

**キャンバス右下に縦積み 3 個**（参照ビジュアルの右下配置を踏襲）。

```
                       ┌────┐
                       │ ⊕  │ 44×44（md 以上 32×32）
                       ├────┤
                       │ ⊖  │
                       ├────┤
                       │ ⟳  │
                       └────┘
```

- `IconButton size="touch"` を 3 個。`bg-surface` + `border-line` + `shadow-md` の 1 枚のカードに
  まとめて浮かせる（背景の図と混ざらないように不透明にする）
- 右下から 12px の余白。**ノードアクションバーが出ているときは、バーの上へ 12px 逃がす**
  （重ならないように）
- ⊕ は最大段（2.0）で `disabled`、⊖ は最小段（0.3）で `disabled`（既存の `disabled:opacity-40` のまま）

## 6. 選択とノードアクションバー

### 6-1. 選択

- ノードをタップ / クリックすると**選択**（同時に 1 個だけ。複数選択は spec 14 でスコープ外）
- 選択中のノード: `ring-2 ring-accent`（`ring-offset` は付けない。図の上では offset が背景を切り抜いて見えるため）
- 背景をタップ / Escape で選択解除
- **「どれが選択中か」を色だけで伝えない** — 下端のアクションバーに名前が出るのがテキストの手がかり

### 6-2. ノードアクションバー

**決定: 選択中は画面下端に固定のバーを出す。PC でも同じバーを使う（ポップオーバーにしない）。**

```
375px（2 行に折り返す）
┌────────────────────────────────────────┐
│ ▌ 田中 太郎   主人公                [✕] │ 44px
│ [＋ 関係][この人だけ][グループ][編集]     │ 44px
└────────────────────────────────────────┘

md 以上（1 行に収まる）
┌──────────────────────────────────────────────────────────┐
│ ▌ 田中 太郎  主人公   [＋ 関係][この人だけ][グループ][編集] [✕] │
└──────────────────────────────────────────────────────────┘
```

- **なぜノードの近くに出すポップオーバーにしないか**: ノードの周りは図の中で最も読みたい場所
  （その人につながる線が集まっている）。そこを UI で塞ぐと、選択した瞬間に見たいものが消える。
  下端固定なら図を一切隠さない（隠すのはバーの高さぶんだけ）
- 375px / PC の出し分けは `flex-wrap` だけ。**JS の分岐を作らない**
- 面は `bg-surface` + `border-line` の上枠 + `shadow-lg`（図の上に乗るので不透明にする）
- `▌` は識別色の縦帯（`aria-hidden`）。名前は `text-sm font-medium truncate`、立ち位置は `text-[11px] text-muted`

| ボタン | 動作 |
| --- | --- |
| `＋ 関係` | **結線モード**に入る（[7 章](#7-結線操作)） |
| `この人だけ` | **フォーカス表示**に入る（[9 章](#9-フォーカス表示と全体表示の往復)）。押下中は `aria-pressed="true"` |
| `グループ` | グループ割り当ての `Modal` を開く（[11 章](#11-グループ枠の作成割り当て管理)） |
| `編集` | **キャラクター管理ドロワー（`CharacterPanel`）を開く**。相関図側に入力欄は作らない（spec 5） |
| `✕` | 選択解除（`IconButton label="選択を解除"`） |

- **`編集` の追加要件**: `CharacterPanel` は全キャラの一覧なので、開いただけでは目的の人が
  どこにあるか分からない。**該当キャラの行までスクロールし、`ring-2 ring-accent` を約 1.5 秒
  当てて示す**こと。これが無いと「編集」が実質使えない
- **選択したノードがアクションバーに隠れる位置にある場合**、キャンバスを最小限だけパンして
  ノードがバーの上に来るようにする（自動で全体が動くのは不快なので、必要な分だけ）

## 7. 結線操作

**2 つの経路を用意する。タップ 2 段階が必須経路、ドラッグは PC の高速手段（spec 8）。**

### 7-1. タップ 2 段階（全端末共通・これが必須経路）

| 手順 | 操作 | 画面 |
| --- | --- | --- |
| 1 | 始点のノードをタップ | 選択リング + ノードアクションバーが出る |
| 2 | アクションバーの `＋ 関係` を押す | **結線モード**に入る。キャンバス上端に `bg-accent text-accentfg` のバーが出る:「**「田中 太郎」とつなぐ相手を選んでください**  [キャンセル]」。始点ノードは `ring-accent` のまま、**始点ノード自身は `opacity-40` + タップ無効**（自己ループ禁止をエラーではなく「そもそも選べない」で表現する） |
| 3 | 相手のノードをタップ | 関係が 1 本作られ、**関係編集モーダル**が開く（[7-3](#7-3-関係編集モーダル)） |
| 4 | ラベルを入れて閉じる | ラベルは**空でもよい**（spec 1）。保存ボタンは無い（デバウンス保存） |

**誤操作の戻し方**

| いつ | どう戻すか |
| --- | --- |
| 手順 2 のあと（相手を選ぶ前） | 上端バーの `キャンセル` / `Escape` / **キャンバス背景をタップ**。何も作られない |
| 手順 3 のあと（作ってしまった） | 開いた関係編集モーダルの **`この関係を削除`**。**Undo が無いので、ここが「作った直後に取り消す」唯一の経路**。だからモーダルには必ず削除を置く |
| 相手を間違えた | 削除してやり直す。または関係編集モーダルの **`入れ替え`**（from / to を入れ替える。矢印の向きを直す唯一の手段） |

- 結線モード中は**ズーム / パンは効いたまま**（画面外の相手を選べるようにするため）。
  ノードの移動だけは無効化する（結線と移動が同じ操作になってしまうため）
- 結線モードは**この経路を PC でも使える**。マウスでもドラッグせずに結線できる

### 7-2. ドラッグ結線（`md` 以上のみ）

- ノードにホバーすると、**右辺の中央に結線ハンドル**（直径 14px の円、`bg-accent` + `border-surface` 2px）が出る
- **ハンドルは 1 個だけ**。エッジの端点はノード矩形との交点で計算するので、ハンドルの位置は
  線の見た目に影響しない。4 辺に置いても情報が増えないぶん、ノードが窮屈になるだけ
- ハンドルからドラッグ → カーソルまで **`accent` の破線ガイド**を引く。ドロップ可能なノードは `ring-2 ring-accent`
- 有効なノードで離す → [7-3](#7-3-関係編集モーダル) が開く（タップ経路の手順 3 と同じ）
- **自分自身 / 背景で離す → 何も作らずガイドが消える。エラーメッセージを出さない**（何も起きなかっただけ）
- **`md` 未満ではハンドルを一切出さない**。理由: ホバーが無い端末で常時表示すると図が点で埋まり、
  かつ 44px にするとノードより大きくなる。375px の結線は 7-1 が担う
- ハンドルの当たり判定は視覚 14px に対し **24px**（透明パディング）。**44px を満たさないが、
  `md` 以上のポインタ専用要素なので対象外**（[14 章](#14-タップ領域-4444px-の一覧)）

### 7-3. 関係編集モーダル

`Modal`（`title="関係"`）を使う。結線直後・エッジのラベル箱タップ・関係リストからの遷移で共通。

```
┌──────────────────────────────────┐
│ 関係                         [✕] │
├──────────────────────────────────┤
│ ● 田中 太郎  →  ● 鈴木 花子       │  読み取り専用（識別色ドット + 名前）
│                    [ 入れ替え ]  │
│                                   │
│ ラベル                            │
│ [ 兄妹 ______________________ ]  │  InlineText（枠付き・デバウンス保存）
│                                   │
│ 向き                              │
│ [ A → B ][ A ↔ B ][ 線のみ ]     │  SegmentedControl（size="touch"）
│                                   │
│ [ この関係を削除 ]        [閉じる] │
└──────────────────────────────────┘
```

- 向きのラベルは**記号だけにしない**。`A → B` の `A` / `B` は実際のキャラクター名に置き換える
  （例: `田中 太郎 → 鈴木 花子`）。長いときは `truncate`
- `この関係を削除` は `Button variant="danger"`
- **保存ボタンを置かない**。ラベルはデバウンス保存、向きは押した瞬間に反映

## 8. ノード移動とキャンバスパンの分離（375px の最大の緊張点）

企画部が名指しした新しい緊張点（spec 8 / 16）。**掴む対象で分ける**が基本方針だが、
それだけでは 375px で成立しないので 5 つの仕掛けを重ねる。

### 8-1. 基本ルール

| ポインタを下ろした場所 | 起きること |
| --- | --- |
| **ノードの上** | ノードの移動 |
| **背景（ドットグリッド）の上** | キャンバスのパン |
| **グループ枠の上（ノードの無い場所）** | **パン**（枠は表示専用で、掴めない。枠だけを動かす概念が無いため） |
| **2 本指（どこでも）** | ピンチズーム。ノードの上から始まっても移動より優先する |

**操作は開始時に確定し、途中で切り替わらない**（ポインタキャプチャ）。指がノードから外れても
移動は続き、背景から始めたパンはノードの上を通っても移動にならない。

### 8-2. 重ねる 5 つの仕掛け

1. **ドラッグ開始しきい値 8px。** 8px 動くまで移動もパンも始めない。8px 未満で離せば「タップ」。
   既存カンバンの `activationConstraint: { distance: 6 }` と同じ考え方で、指なので少し大きくする。
   **これがタップ選択とドラッグ移動を両立させている中核**（外すと選択できなくなる）
2. **縮小表現（zoom < 0.6）ではノードを動かせない。** 0.3 倍で指を 1px 動かすと論理座標が 3px 動く。
   精密配置が成立しないうえ、ノードが小さくて取り違えが最悪化する帯域。
   **全体表示は「見る」ためのモードと割り切る。** 動かしたければ ⊕ でズームインするか、
   フォーカス表示に入る。**spec 14-10「375px でノード移動が可能」には反しない**（ズームすれば可能）
3. **ノードの当たり判定は、ズーム倍率にかかわらず最小 44 × 44 スクリーン px を保証する。**
   見た目が 36px でも判定は 44px。既定配置のピッチ（200 × 120 論理）なら zoom 0.6 でも
   スクリーン 120 × 72px の間隔があり、44px の判定同士は重ならない。
   作者が密着させて置いた場合だけ重なるが、**そのときは後に描かれた（配列で後の）ノードが勝つ**。
   誤タップしても起きるのは選択の変化だけで、破壊的ではない
4. **移動中は視覚が明確に変わる。** 掴んだノードに `shadow-lg` + `ring-2 ring-accent`。
   パン中は背景を変えない（PC はカーソルを `grabbing` に）。
   **「今どっちをしているか」が 1 フレームで分かる**ので、間違いに気づいて指を戻せる
5. **PC は Escape で移動を中止**（元の位置に戻す）。**スマホには中止手段が無い**ことを正直に認める
   — Undo が無いため、動かしてしまったら手で戻すしかない。だから 1〜4 で**発生確率を下げる方向**に
   全振りしている

### 8-3. 保存のタイミング

- **ドラッグ終了時に 1 回だけ**座標をストアへ書く。移動中は書かない
  （書くと `updatedAt` が毎フレーム進み、作品一覧の並びが暴れる）
- **8px しきい値未満のタップでは書かない**（見ただけ・触っただけで `updatedAt` が進まない。spec 2）

### 8-4. ページのスクロールを起こさない

キャンバスは `touch-action: none` 相当（1 本指パン・ピンチを自前で扱うため）。
**375px で body に縦スクロールが漏れないこと**は
[07-drag-and-drop.md](../../../docs/02-development-docs/07-drag-and-drop.md) の
`touch-none` と同じ注意点（実装方式を問わず要件）。

## 9. フォーカス表示と全体表示の往復

**spec 8 の 2 段構えの実装。ワンタップで往復すること。**

| | 全体表示 | フォーカス表示 |
| --- | --- | --- |
| 何を見るか | 構造（誰が中心か / どの陣営がどこか） | 1 人の直接のつながり |
| 描くもの | 全ノード・全エッジ・全グループ枠 | **選択キャラ + そのキャラと直接つながっている相手だけ**。それらの間のエッジだけ |
| 375px での倍率 | 全体が収まる倍率（30 人で約 0.43 → 縮小表現） | **文字が読める倍率**（下記） |
| 入り方 | 初期状態 / `⟳` / ツールバーの `◀ 全体表示` | ノード選択 → アクションバーの `この人だけ` |

### 9-1. フォーカス表示の作り方

- **座標は動かさない。** 保存された配置をそのまま使う（勝手に並べ替えると作者の図が壊れる）
- 表示対象ノードの外接矩形に **zoom-to-fit**。ただし **0.8 〜 1.5 にクランプ**（0.8 が文字の読める下限）
- **選択したキャラを画面中央に置く**。これで 0.8 で収まらない場合でも「中心人物 + 近い相手」は必ず読める
- 対象外のノード・エッジは**描かない**（薄くして残さない）。375px では薄い残骸も図を埋める
- グループ枠は**表示対象のノードだけで再算出する**（描いていないメンバーを囲まない）
- フォーカス中も **ノードの移動・結線・パン・ズームはできる**（PC 限定機能を作らない）

### 9-2. 帰り道

- ツールバー左に **`◀ 全体表示`** を出す（**フォーカス中だけ**）。テキスト付きなので
  「今フォーカス中である」ことが色ではなく文字で分かる
- 右下の **`⟳`** も同じ動作（フォーカス解除 + 全体が収まる倍率と位置）
- `Escape`（キャンバスにフォーカスがあるとき）も同じ
- **つながりが 0 本のキャラで `この人だけ` を押した場合**: そのキャラ 1 個だけが中央に出る。
  空にはしない。加えて上部に 1 行:「このキャラクターにはまだ関係がありません。」
  + `＋ 関係を追加` ボタン

### 9-3. 保存しないもの

フォーカス状態・倍率・パン位置は保存しない（spec 2 / 10-3）。

## 10. 関係リスト（エッジ編集の代替経路・v1 必須）

**決定: `Drawer` を使う。375px でも PC でも同じ。新しいプリミティブは作らない。**

- **なぜ図から線をタップさせないか**: 企画部の指摘どおり、375px で細い線を正確にタップするのは
  現実的でなく、ラベル箱を 44px 角にすれば図が箱で埋まる（spec 8）。**リストが 375px で
  関係を確実に選べる唯一の手段**
- **なぜ `Drawer` か**: 375px では実質フルスクリーンになり、N 件の編集に十分な面積が取れる。
  PC でも右 448px に出る。既存プリミティブで足りるので新設しない
- PC では図から直接エッジをクリックできるため、リストを開きっぱなしにする必要が低い。
  **併置（PC で図と並べる）は v2 の余地として残す**（今回は実装分岐を作らない）

### 10-1. 開き方

- キャンバスツールバー右の **`関係 N`** ボタン（`N` は件数、`text-muted text-xs tabular-nums`。
  ヘッダの「キャラクター 3」と同じ形）
- ノードを選択している状態で開くと、**そのキャラクターの関係だけに絞られた状態**で開く
  （図で見つけた線を編集したい、という導線をつなぐ）

### 10-2. 中身

```
┌───────────────────────────────────┐
│ 関係                          [✕] │
├───────────────────────────────────┤
│ [ すべて 12 ][ 田中 太郎 4 ]       │ ← SegmentedControl（選択中のキャラが居るときだけ 2 個目）
├───────────────────────────────────┤
│ ● 田中 太郎  →  ● 鈴木 花子   [✕] │
│ [ 兄妹 ________________________ ] │ ← InlineText（枠付き）
│ [ 田中→鈴木 ][ ↔ ][ 線のみ ] [入替] │ ← SegmentedControl + 入れ替え
├───────────────────────────────────┤
│ ● 鈴木 花子  →  ● 佐藤 健     [✕] │
│  …                                │
├───────────────────────────────────┤
│ ＋ 関係を追加                      │
│ [ 誰から ▾ ] → [ 誰へ ▾ ] [ 追加 ] │ ← Select ×2（min-h-11）+ Button
└───────────────────────────────────┘
```

- **行はその場で編集できる**（別モーダルを開かせない）。「編集は流れを止めない」原則
- 並び順は**保存された配列順**（spec 10-1）。表示上の並べ替えはしない
  （並べ替えると「さっき足したのはどれか」が分からなくなる）
- `＋ 関係を追加` の `Select` 2 つは、**選んだ時点では追加しない**。`追加` を押して初めて作る
  （2 つ選ぶまで不完全なため）。同じ人を両方に選んだら `追加` を `disabled`
  （自己ループ禁止をエラーではなく「押せない」で表現）
- 追加した行は**リスト末尾に付き、`ring-accent` を約 1.5 秒当てて示す**（どれが増えたか分かるように）
- 各行の `✕` は削除（確認あり。[13 章](#13-削除確認の文言)）
- 関係 0 件のとき: `EmptyState` を使わず、`text-muted text-xs` の 1 行
  「まだ関係がありません。下の「＋ 関係を追加」か、図でノードを選んで「＋ 関係」から作れます。」

## 11. グループ枠の作成・割り当て・管理

### 11-1. 割り当ては「ノード側から」

**決定: グループへの出し入れは、ノードを選んで `グループ` を押す経路に一本化する。**

- 理由: 思考の単位が「このキャラをどこに入れるか」であること。加えて、`groupId` は
  `Character` 側に持つ型（spec 10-2）なので、グループ側からメンバーを複数選ぶ UI は
  データの持ち方と噛み合わない
- UI は `Modal`（`title="グループに入れる"`）。1 タップで確定して閉じる

```
┌────────────────────────────────┐
│ グループに入れる            [✕] │
├────────────────────────────────┤
│ ○ 未所属                        │
│ ● 王国側              （5 人）  │ ← 現在の所属に ● と font-semibold
│ ○ 帝国側              （3 人）  │
│ ○ 〇〇家              （0 人）  │
├────────────────────────────────┤
│ ＋ 新しいグループを作って入れる   │
│ [ グループ名 ______ ] [ 作成 ]  │
└────────────────────────────────┘
```

- 各行は 44px 高。**`○ / ●` の記号 + `font-semibold` の二重表現**で現在の所属を示す（色だけに頼らない）
- `＋ 新しいグループを作って入れる` は、押すと入力欄が開く（最初から開いていると
  既存グループを選ぶ導線が埋もれる）

### 11-2. グループ管理ドロワー

キャンバスツールバー右の **`グループ N`** ボタンから `Drawer`（`title="グループ"`）。

```
┌───────────────────────────────────┐
│ グループ                      [✕] │
├───────────────────────────────────┤
│ [ 王国側 ______________ ]  5 人 [✕]│ ← InlineText（枠付き）+ 人数 + 削除
│ [ 〇〇家 ______________ ]  0 人 [✕]│
│   （メンバーなし・図には出ません）   │ ← text-muted text-xs
├───────────────────────────────────┤
│ [ ＋ グループを追加 ]              │
└───────────────────────────────────┘
```

- **行にポインタを乗せる / フォーカスすると、キャンバス上のその枠が `accent` でハイライトされる**
  （枠が重なっているとき、どれが自分の枠か分かる唯一の手段）
- メンバー 0 のグループは**作れる**（spec 7）。図には出ないことを行内に明記する
- `＋ グループを追加` で空名のグループが 1 件増え、`InlineText` に `autoFocus`
  （`CharacterPanel` の `＋ 追加` と同じ流儀）

## 13. 削除確認の文言

**形式は既存に合わせて `window.confirm`**（[04-error-handling.md](../../../docs/02-development-docs/04-error-handling.md)
の現行流儀）。auth-screens 側で確認モーダル化が決まった場合は**そこで一括して置き換える**
（相関図だけ先に別形式にしない）。

**すべての文言に「元に戻せません」を入れる**（取り消し機能が無いため）。

| 操作 | 文言 |
| --- | --- |
| 関係の削除（ラベルあり） | `この関係「兄妹」を削除します。元に戻せません。よろしいですか？` |
| 関係の削除（ラベル空） | `「田中 太郎」→「鈴木 花子」の関係を削除します。元に戻せません。よろしいですか？` |
| グループの削除 | `グループ「王国側」を削除します。所属していた 5 人は未所属に戻ります（キャラクターは消えません）。元に戻せません。よろしいですか？` |
| グループの削除（メンバー 0） | `グループ「〇〇家」を削除します。元に戻せません。よろしいですか？` |

### キャラクター削除の確認文言の更新（spec 11 の要求・**必須**）

現行（[CharacterPanel.tsx](../../../../src/components/CharacterPanel.tsx)）:

> `「{name}」を削除します。各シーンからも外れます。よろしいですか？`

これでは**相関図の関係が一緒に消えることが伝わらない**。次に変える。

| 条件 | 文言 |
| --- | --- |
| 関係が 1 件以上ある | `「田中 太郎」を削除します。各シーンから外れ、相関図の関係 4 件も消えます。元に戻せません。よろしいですか？` |
| 関係が 0 件 | `「田中 太郎」を削除します。各シーンからも外れます。元に戻せません。よろしいですか？` |

- **件数を出す**（`4 件`）。0 件のときは相関図の話を出さない（無関係な不安を与えない）
- 「元に戻せません」は**両方に入れる**（現行文言にも欠けていたので、この機会に足す）

## 14. タップ領域 44×44px の一覧

`md` 未満で表示・到達しうる要素はすべて満たすこと（WCAG 2.5.5 相当、
[mobile-vertical-list 決定 8](2026-08-04-mobile-vertical-list.md) と同じ基準）。

| 要素 | 最小サイズ | 実現方法 |
| --- | --- | --- |
| モード切替「構成 / 相関図」 | 各 44 高 | `SegmentedControl size="touch"` |
| ツールバー `◀ 全体表示` / `グループ N` / `関係 N` | 各 44 高 | `Button size="touch"` |
| 浮遊コントロール `⊕` / `⊖` / `⟳` | 各 44×44 | `IconButton size="touch"` |
| **ノード** | **44×44（ズーム倍率を問わず）** | 見た目が小さくても当たり判定は 44px を確保する（[8-2](#8-2-重ねる-5-つの仕掛け) ③） |
| ノードアクションバーの各ボタン | 各 44 高 | `Button size="touch"` / `IconButton size="touch"` |
| 結線モードの `キャンセル` | 44 高 | `Button size="touch"` |
| 関係リストの行内 `InlineText` / 向き 3 択 / `✕` | 各 44 高 | `SegmentedControl size="touch"`、`InlineText` は `min-h-11` |
| 関係リストの `誰から` / `誰へ` `Select` | 44 高 | `className="min-h-11"`（`INPUT_CLASS` の `py-2` では届かない） |
| グループ割り当ての各行 | 44 高 | 素の `<button>` に `min-h-11`（`Button` は `justify-center` のため左寄せに使えない） |
| 関係編集モーダルの各操作 | 44 高 | `Button size="touch"` / `SegmentedControl size="touch"` |

### 44px を満たさない要素（理由と代替手段）

| 要素 | 実サイズ | なぜ満たせないか | 代替手段 |
| --- | --- | --- | --- |
| **エッジのラベル箱** | 描画サイズどおり（高さ 約 20 スクリーン px @zoom 1.0） | 44px 角にすると図がラベル箱で埋まり、図の可読性が失われる（企画部が spec 8 で同じ指摘をしている） | **① 関係リスト**（`関係 N` ボタン → 全件、またはノード選択 → そのキャラの関係だけ）が確実に届く経路。**② ラベル箱タップは補助経路**として残す（当たれば関係編集モーダルが開く。当たらなくても損をしない） |
| **エッジの線そのもの** | 1〜2 スクリーン px | 同上。透明な当たり判定を 44px 幅で重ねると、線の周囲 44px が全部タップ不能領域になる | `md` 以上では 24px 幅の透明ストロークで線をクリック可能にする（ポインタ専用）。`md` 未満では**線をタップ対象にしない**。代替は上と同じ関係リスト |
| **ドラッグ結線ハンドル** | 24px（視覚 14px + 透明パディング） | `md` 以上のポインタ専用要素で、`md` 未満では**そもそも表示しない**ため対象外 | `md` 未満の結線は [7-1](#7-1-タップ-2-段階全端末共通これが必須経路) のタップ 2 段階 |

**これら 3 つはいずれも「タップできないと機能が使えない」状態を作らない。**
375px で関係を追加 / 編集 / 削除する経路（タップ 2 段階 + 関係リスト）は 44px を満たしている。

## 15. デザイントークンとコントラスト

### 15-1. 使うトークン

すべて既存のセマンティックトークン（[globals.css](../../../../src/app/globals.css)）。
**新しい色を 1 つも足さない。生の色ユーティリティ（`text-gray-500` 等）を使わない。**

| 用途 | トークン |
| --- | --- |
| キャンバス背景 | `bg-bg` |
| ドットグリッド | `line` |
| ノードの面 / ラベル箱 / バー / 浮遊コントロール | `bg-surface` |
| ノードの枠 | `border-line` |
| グループ枠の線 | `border-muted` |
| グループ枠の塗り | `bg-surface2/60` |
| エッジ線・矢じり | `muted` |
| ノード名・ラベル文字・グループ名 | `text-fg` |
| 立ち位置・件数・ヒント文 | `text-muted` |
| 選択 / 結線モード / アクティブなセグメント | `accent` / `accentfg` |
| 削除 | `danger` |

### 15-2. 「データとしての色」の例外

**キャラクター識別色（`CHARACTER_COLORS`、[types.ts](../../../../src/lib/types.ts)）だけが例外。**
`style={{ background: character.color }}` で適用する。既存のシーンチップ・縦リストと同じ扱い。

| 使い方 | 場所 |
| --- | --- |
| ノード左端の 6px 帯 | 通常表現のノード |
| ノード全体のベタ塗り | **縮小表現のノードのみ** |
| 色ドット（8px 円） | アクションバー・関係リスト・関係編集モーダル |

- **新しい色を増やさない。** 10 色のまま
- **エッジ・グループ枠には識別色を使わない**（[3-3](#3-3-エッジ関係) の理由）

### 15-3. コントラスト検証（ライト / ダーク両方）

チケットの完了条件「文字色と背景のコントラスト比 ≥ 4.5:1」の実測。

| 組み合わせ | ライト | ダーク | 判定 |
| --- | --- | --- | --- |
| ノード名 `text-fg` on `bg-surface` | `#14171c` / `#ffffff` = **16.9:1** | `#e7e9ec` / `#161a20` = **13.4:1** | ✅ |
| 立ち位置 `text-muted` on `bg-surface` | `#6b7280` / `#ffffff` = **4.83:1** | `#97a0ad` / `#161a20` = **7.0:1** | ✅ |
| ラベル箱の文字 `text-fg` on `bg-surface` | 同上 16.9:1 | 同上 13.4:1 | ✅ |
| グループ名 `text-fg` on `bg-bg`（ラベルチップ） | `#14171c` / `#f5f6f8` = **15.6:1** | `#e7e9ec` / `#0d0f13` = **15.3:1** | ✅ |
| ヒント文 `text-muted` on `bg-surface` | 4.83:1 | 7.0:1 | ✅ |

**非テキスト（WCAG 1.4.11 の 3:1 が適用）**

| 組み合わせ | ライト | ダーク | 判定 |
| --- | --- | --- | --- |
| エッジ線 `muted` on `bg` | 約 **4.5:1** | 約 **8.7:1** | ✅ |
| グループ枠線 `muted` on `bg` | 同上 | 同上 | ✅ |
| 縮小表現ノードの `muted` 輪郭 on `bg` | 同上 | 同上 | ✅ |
| 選択リング `accent` on `bg` | `#4f46e5` / `#f5f6f8` = 約 **7.4:1** | `#7d81f5` / `#0d0f13` = 約 **6.3:1** | ✅ |

### 15-4. **開放質問 3 への回答**（識別色を背景に使ったときのコントラスト）

チケットの開放質問「ノード内テキスト / エッジラベルが、**識別色を背景に使った場合でも**
ダーク / ライト両方で 4.5:1 を満たせるか」への回答:

> **満たせない。だから識別色をテキストの背景に使わない設計にした。**

- 実測例: `#f59e0b`（`CHARACTER_COLORS` の 3 番目）on ライト背景 `#f5f6f8` は **約 2.0:1**。
  この上に `#ffffff` の文字を置くと約 2.2:1、`#14171c` の文字なら約 7.7:1 と、**色によって
  白文字が良いか黒文字が良いかが逆転する**。10 色ぶんの分岐を書けば技術的には満たせるが、
  「色が変わると文字色まで変わる」ノードは図として落ち着かない
- **本稿の答え**: 通常表現では**識別色を 6px の帯にとどめ、面は `surface` 固定**にする。
  縮小表現では**テキストを描かない**のでコントラスト要件の対象外になり、10 色すべてを安全に使える。
  ただし色によっては背景と紛れる（上記 2.0:1）ので、**`muted` の 1px 輪郭を必ず描いて
  境界のコントラストを 4.5:1 にする**

### 15-5. 実装時の落とし穴（ライトモード限定）

- **`text-muted` を `bg-surface2` の上に置かない。** ライトで `#6b7280` / `#eef0f4` = **約 4.2:1** と
  AA を下回る（`bg-surface` の白なら 4.83:1 で通る）。ダークでは 6.0:1 で問題ない。
  本稿では「立ち位置」「ヒント文」を必ず `bg-surface` の上に置くことでこれを回避している
- **`border-line` を `bg-bg` の上に引かない**（ライトで **1.05:1**、事実上見えない）。
  グループ枠と縮小表現ノードの輪郭を `muted` にしているのはこのため

## 16. アクセシビリティ

| 項目 | 実装 |
| --- | --- |
| アイコンのみのボタン | `IconButton` を使う（`aria-label` + `title`）。`⊕`=「拡大」/ `⊖`=「縮小」/ `⟳`=「全体表示に戻す（ノードの配置は変わりません）」 |
| ダイアログ | `Modal` / `Drawer` をそのまま使う（`role="dialog"` + `aria-modal` + Escape 済み） |
| キャンバス | ラッパに `tabIndex={0}` + `role="application"` + `aria-label="キャラクター相関図"` |
| キーボードでのパン | キャンバスにフォーカスがあるとき **矢印キーで論理 40px ずつ**（パン十字ボタンの代替） |
| キーボードでのズーム | `+` / `-` で段を移動、`0` で全体表示に戻す |
| ノードの到達 | ノードは **Tab で順に辿れ**（DOM 順 = `characters` 配列順）、**Enter / Space で選択**できること。実装方式を問わない要件（[17 章](#17-dev-へ渡す-ui-要件リスト実装方式非依存) ⑬） |
| 装飾用の色ドット・色帯 | `aria-hidden="true"` |
| 色だけで状態を伝えない | 選択 = リング + **アクションバーに名前が出る** / 向き = **矢じりの形**（色ではない）+ モーダルの文字ラベル / グループ = **枠 + 名前の文字** / フォーカス中 = **`◀ 全体表示` というテキストが出る** / セグメントの選択中 = 面の色 + `font-semibold` |
| コントラスト | [15-3](#15-3-コントラスト検証ライト--ダーク両方) の実測どおり全項目 AA 以上 |

### キーボードだけで完結する編集経路（明示）

図のドラッグはキーボードでは行えない。**それでも v1 の全操作がキーボードで完結すること**を
次で担保する。

| やること | キーボードでの経路 |
| --- | --- |
| 関係の追加 / ラベル編集 / 向き変更 / 削除 | **関係リスト**（`Drawer`。すべて `Select` / `InlineText` / `Button`） |
| グループの作成 / 名前編集 / 削除 | **グループ管理ドロワー** |
| グループへの割り当て | ノードを Tab で選択 → アクションバーの `グループ` → `Modal` の行を Tab + Enter |
| フォーカス表示の往復 | ノードを Tab で選択 → `この人だけ` / `Escape` |
| **ノードの配置** | **できない。** ノードの座標をキーボードで動かす手段は v1 では作らない。**図は「見る」ためのもので、配置は表現の調整であり、それが無くても相関の情報は関係リストで完全に読める** — これを許容範囲と判断した（既存のカンバンもキーボード並べ替えは未対応。[06-ui-design.md](../../../docs/02-development-docs/06-ui-design.md) §5） |

## 17. dev へ渡す UI 要件リスト（実装方式非依存）

**本稿は方式を決めない**（秘書決裁 D-6）。dev は移行方針チケットで、
下記 20 項目を満たせるかで方式（React Flow / 自前 SVG / HTML オーバーレイ / その他）を選ぶこと。
**満たせない項目があるなら、その項目を落としてよいかをデザイン部へ差し戻す。**

### 描画

1. 論理座標 ↔ スクリーン座標の変換（パン + ズーム）を持ち、ノード / エッジ / グループ枠 /
   ラベルを**同じ変換**で描ける
2. **ズームに追従しない要素を混在できる** — グループのラベルは固定サイズ、矢じりと線幅は
   クランプ（[4 章](#4-ズームと-2-段階の見え方-lod) / [3-3](#3-3-エッジ関係)）。**方式選定で最初に確認すべき項目**
3. z 順を **グループ枠 → エッジ線 → ノード → ラベル箱 → 選択装飾** に固定できる
4. グループ枠を**メンバーの外接矩形から毎回算出して描ける**（データに持たない。spec 7）。
   面積の大きい枠から描ける
5. エッジの端点を**ノード矩形の境界でクリップ**できる（中心同士を結んで交点で切る）
6. 同一ペアの複数エッジを**法線方向に平行オフセット**して描ける
7. ノードの見た目を**アプリのセマンティックトークンで自由に組める**
   （ライブラリ既定のスタイルを打ち消すために CSS を上書きする必要が無いこと）
8. ライブラリ付属の UI（ミニマップ / コントロール / 背景 / アトリビューション等）を
   **使わずに済む**（使うとトークン外の見た目が図に混ざる）
9. ズーム倍率に応じて**ノードの描画内容そのものを差し替えられる**（通常表現 ⇄ 縮小表現）

### 操作

10. **背景（パン）とノード（移動）を、掴んだ対象で分離**できる。開始後は切り替わらない
11. ドラッグ開始しきい値（**8px**）を設定できる
12. ノードから**「結線」という別ジェスチャ**を開始でき、ドラッグ中のガイド線を描ける（`md` 以上）
13. **ノードは Tab で順に辿れ、Enter / Space で選択できる**（DOM 順 = 配列順）
14. キャンバス自体が `tabIndex` を持ち、**矢印キーでパン / `+` `-` でズーム / `0` で全体表示**
15. **ノードの当たり判定を、ズーム倍率にかかわらず最小 44×44 スクリーン px に保てる**
    （見た目より広い透明領域）
16. エッジのラベル箱が**クリック / タップ対象**になれる
17. **任意のノード集合に zoom-to-fit** できる（フォーカス表示・全体表示の両方で使う）
18. **表示するノード / エッジの集合を差し替えられる**（フォーカス表示は描画対象を絞る。
    薄くするのではなく描かない）

### 環境・性能

19. 375px でタッチの**ピンチズーム / 1 本指パン**が効き、**ページ全体のスクロールを起こさない**
    （`touch-action` の制御ができる）
20. Next.js 16.3 / React 19.2 の App Router で、`"use client"` 配下だけで完結し **SSR で落ちない**。
    かつ 30 ノード / 60 エッジ規模で 375px の描画・ドラッグが滑らか
    （既存ボードと同居する。[08-performance-optimization.md](../../../docs/02-development-docs/08-performance-optimization.md) の想定規模）

### 保存の約束（UI 側からの要求）

21. **ノードのドラッグ確定時に 1 回だけ**座標をストアへ書く。ドラッグ中は書かない
22. **8px しきい値未満のタップでは書かない**（見ただけで `updatedAt` が進まない。spec 2）

## 18. 実装側で判断が要る点 / 未確認

### デザイン部から dev への申し送り

1. **未配置ノードの既定位置**は [3-5](#3-5-未配置ノードの既定位置デザイン部の推奨最終判断は-dev) が
   推奨値。要件（乱数を使わない / 重ならない / 配列順を根拠にしてよい）を満たせば別式でもよい。
   ただし**列数を n 依存にしない**こと（キャラを足すと既存の未配置ノードが全部動く）
2. **`SegmentedControl` は `ui.tsx` に足す**。SceneEditor のステータス 3 択の置き換えは
   このチケットでは**やらない**（デグレのリスクを負わない）
3. `CharacterPanel` に「特定のキャラの行までスクロールしてハイライトする」機能を足す必要がある
   （[6-2](#6-2-ノードアクションバー) の `編集`）。props の追加が要る
4. キャラクター削除の確認文言に**関係の件数**を出すため、`CharacterPanel` が関係データを
   参照できる必要がある（[13 章](#13-削除確認の文言)）。props で件数だけ渡す形で足りる

### 実機で確認したいこと（デザイン部の未確認事項）

チケットの開放質問への対応状況。

| # | 開放質問 | 本稿での扱い |
| --- | --- | --- |
| 1 | 375px でノードのドラッグとキャンバスのパンを取り違えずに操作できるか | **設計で 5 つの仕掛けを重ねた**（[8-2](#8-2-重ねる-5-つの仕掛け)）が、**8px というしきい値の妥当性は実機でしか決まらない**。実装後に社長のスマホ実機で確認し、必要なら 6〜12px の範囲で調整する |
| 2 | 375px の全体表示で 20〜30 人規模の図が「構造として読める」か | **未確認**。30 人なら約 0.43 倍で縮小表現に入る計算（[3-5](#3-5-未配置ノードの既定位置デザイン部の推奨最終判断は-dev)）。**グループのラベルだけズームに追従しない**設計がこの問いへの主な答えだが、実機で読めるかは要確認。読めなければ「グループ名も読めない全体表示」になるので、そのときは v2 の「相関図に出さないフラグ」（spec 15）を前倒しする判断が要る |
| 3 | 識別色を背景に使ってもコントラスト 4.5:1 を満たせるか | **[15-4](#15-4-開放質問-3-への回答識別色を背景に使ったときのコントラスト) で回答済み（満たせない → 背景に使わない設計にした）** |
| 4 | 既存プリミティブで足りるか | **[1 章](#1-既存プリミティブの再利用可否先に確認) で回答済み（`SegmentedControl` の 1 つだけ足りない）** |

### 企画部に確認したい点（**ブロッカーではない。既定で進めてよい**）

1. **縮小表現（全体表示）でノードのドラッグ移動と結線を禁止する**という判断
   （[4 章](#4-ズームと-2-段階の見え方-lod) / [8-2](#8-2-重ねる-5-つの仕掛け) ②）。
   spec 14-10「375px でノード移動・結線・ラベル編集・グループ割り当てがすべて可能」に対し、
   **「ズームインすれば可能」という形で満たしている**。これを「PC 限定機能を作らない」原則の
   範囲内と読んでよいか。デザイン部の判断は **範囲内**（端末による差ではなく、
   同じ端末内でのモードの差なので）
2. **`CHARACTER_COLORS` は 10 色の循環なので、11 人目以降は縮小表示で個人を識別できない**
   （[4 章](#4-ズームと-2-段階の見え方-lod)）。spec 8 の「全体表示は構造を見るためのもの」という
   定義に照らせば問題ないと読んだが、Q1 の既定「30 人前後で構造が読めること」との整合を
   企画部が是としているかは確認したい
