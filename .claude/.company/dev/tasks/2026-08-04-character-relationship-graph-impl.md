**絶対に外さない点（移行方針の決定より）**

1. **`STORAGE_KEY` も `persist` の `version` も変えない。** `version` を上げると、
   `local-final` に戻したときに **IndexedDB が空で上書きされる**（決定 2-1・C-5）。
   代わりに `merge` で「相関の 2 配列が必ず存在する」ことを保証する。
   **`merge` は `...current` を必ず含める**（落とすとストアのアクションごと消える）。
   **`merge` は絶対に例外を投げない**（投げると `hydrated` が永久に `false` になり「読み込み中…」で止まる）。
2. **`partialize` は 1 文字も変えない。** 相関データは `Project` の中なので自動的に保存される。
3. **`EXPORT_FORMAT` / `EXPORT_VERSION = 1` は据え置き。** 上げても
   `parseProjectJson` は version を読んでいないので実益がゼロ（決定 3-1・C-2）。
4. **ドラッグ中にストアを更新しない。** `persist` は**すべての state 更新で全作品を JSON 化して
   IndexedDB に書く**（C-4）。座標の反映は**ドラッグ終了時に 1 回だけ**。
5. **`withFreshIds` は `{ ...project }` で旧 `relationships` を素通しする。**
   明示的に上書きしないと「線はあるが誰を指すか分からない」状態が JSON に載る（決定 4-2）。
6. **`normalizeProject` の処理順**は グループ → キャラクター → 関係 → ストーリー。
   グループを先に読まないと**全キャラの `groupId` が捨てられる**（決定 3-4）。
7. **`as` を増やさない。** `direction` は型ガード（`isDirection`）で受ける（決定 3-3）。
8. **React Flow で確定**（2026-08-04・Step 2 完了）。実装上の拘束条件:
   - **`useNodesState` / `useEdgesState` を使わない**（作品データの正本は `src/lib/store.ts` のみ）。
     `nodes` / `edges` は毎回導出して渡す controlled 運用
   - **`useStore` の名前衝突に注意**（C-14）。同じファイルでアプリの `useStore`（`@/lib/store`）と
     React Flow の `useStore` を両方使うので、**必ず別名 import**
     （例: `import { useStore as useFlowStore } from "@xyflow/react"`）
   - **LOD（zoom 0.6）は `useFlowStore((s) => s.transform[2] < 0.6)` の真偽値で購読する。**
     `useViewport()` は viewport が変わるたびに再描画されるので**ノードには使わない**
     （型定義に明記・移行方針 C-16 / C-17）。`NodeProps` に zoom は含まれない（C-18）
   - **エッジの線幅・矢じりのクランプ**（design 要件 ②）は連続値が要るので
     `useViewport()` 経由になる。論理値に `clamp(1.5 × zoom, 1, 2) / zoom` を渡す
   - **`<ReactFlowProvider>` で包み、キャンバス本体を子コンポーネントに分ける**
     （フックは Provider の子でしか使えない）
   - **ノードは `node.width` / `node.height` を明示する**（44px の透明な当たり判定が
     measured サイズに混ざると、エッジのクリップと `fitView` の外接矩形が狂う。移行方針 U-9）
   - グループ枠は **`ViewportPortal`** に自前描画（React Flow の親ノード機能は使わない。
     枠の座標を持つことになり spec 7 に反する）。ラベルだけ `scale(1 / zoom)` で固定サイズにする
   - 相関図は **`next/dynamic` で遅延読み込み**する（構成モードの初期ロードを重くしない）

**(b) 既定配置アルゴリズム — design から別案を出した（移行方針 4-3 が「従う」としていた箇所）**

移行方針 4-3 の提案は `cols = Math.ceil(Math.sqrt(total))`。**これは採らないでほしい。**

```
x = 40 + (index % 4) × 200
y = 40 + Math.floor(index / 4) × 120      （index は Project.characters 配列上の位置）
```

| なぜ変えるか | |
| --- | --- |
| **列数を n 依存にしない** | `ceil(sqrt(total))` だと、キャラを 1 人足した瞬間に列数が変わり、**既存の未配置ノードが全部動く**。spec 2 が「末尾追加なので既存の未配置ノードの位置はずれない」を要件にしているので、n 依存は要件違反になる |
| **列数 4 が 375px に最も有利** | 375px は縦長画面なので、図が縦に伸びる方が zoom-to-fit の倍率が上がる。30 人 = 4 列 × 8 行 → 論理 880 × 1020 → 375×503 の viewport に fit すると**約 0.43**。6 列だと約 0.29 まで落ちる |
| ピッチの根拠 | ノード論理サイズ **160 × 60** に対し横 200 / 縦 120。**zoom 0.6 でもスクリーン 120 × 72px の間隔**があり、44px の当たり判定同士が重ならない |

`LayoutOptions` の形（`nodeW` / `nodeH` / `gapX` / `gapY` / `cols`）はそのままでよい。
**要件（乱数を使わない / 重ならない / 配列順を根拠にしてよい / 列数を n 依存にしない）を
満たせば式は dev 判断**。

**(e) レスポンシブは CSS のみ。`matchMedia` による JS 分岐を 1 箇所も作らない**

ブレークポイントで**描画するかどうか**を切り替えるのは 2 箇所だけ:

- **ドラッグ結線ハンドル**（`md` 以上のみ。`md` 未満で常時表示すると図が点で埋まり、44px にすると
  ノードより大きくなる）
- **エッジ線のクリック判定**（`md` 以上のみ 24px 幅の透明ストローク。`md` 未満では線をタップ対象にしない）

それ以外は `size="touch"` / `flex-wrap` / `w-full md:w-auto` で吸収できる（ワイヤーフレーム L 章）。

**(f) 保存タイミングの約束（移行方針の「絶対に外さない点 4」と同じ内容を UI 側からも要求する）**

- **ノードのドラッグ確定時に 1 回だけ**座標を書く。ドラッグ中は書かない
- **8px しきい値未満のタップでは書かない**。「相関図を開いただけ / 触っただけで `updatedAt` が
  進み、作品一覧の並びが変わる」のは誤り（spec 2）
- ズーム倍率 / パン位置 / 選択 / フォーカス状態 / 表示モードは**保存しない**

**④ 決定待ち**

- **実装方式**（React Flow か自前 SVG か）。**Step 2 で dev が最終決定**。design は決めない
- **社長: `@xyflow/react` の依存追加の承認**（移行方針 付録 E-1）。design から追加する条件は無い
- **企画部への確認 2 件**（[ui-spec 19 章](../../design/ui-specs/2026-08-04-character-relationship-graph.md#19-企画-spec-との関係差し戻しはしていない)）。
  **ブロッカーではない。既定で進めてよい**
  1. 縮小表現（全体表示）でノードの移動と結線を禁止する判断が、spec 14-10「375px で
     ノード移動・結線・ラベル編集・グループ割り当てがすべて可能」の範囲内か。
     **design の判断は「範囲内」**（ズームインすれば可能で、端末による差ではなく同じ端末内の
     モード差のため）
  2. `CHARACTER_COLORS` は 10 色の循環なので、**11 人目以降は縮小表示で個人を識別できない**。
     spec 8「全体表示は構造を見るためのもの（文字は読めなくてよい）」に照らせば問題ないと読んだ

**⑤ 開放質問（design が回答できず、実機に持ち越したもの）**

**社長の画面確認に必ず含めること。**

1. **375px でノードのドラッグとキャンバスのパンを取り違えずに操作できるか。**
   ui-spec 8-2 で 5 つの仕掛け（8px しきい値 / 縮小表現では移動禁止 / 当たり判定 44px 保証 /
   移動中の強い視覚変化 / PC は Escape で中止）を重ねたが、**8px というしきい値の妥当性は
   実機次第**。取り違えが起きるなら 6〜12px の範囲で調整する。
   **スマホには移動を中止する手段が無い**（Undo が無く Escape も無い）ことは設計上認めており、
   発生確率を下げる方向に全振りしている。実機で破綻したら design へ差し戻す
   （移行方針 U-3 と同じ項目。**方式の判定も覆しうる**）
2. **375px の全体表示で 20〜30 人規模の図が「構造として読める」か。**
   30 人なら約 0.43 倍で縮小表現に入る計算。**グループのラベルだけズームに追従しない**設計が
   主な答えだが、実機で読めなければ v2 の「相関図に出さないフラグ」（spec 15）の前倒しを検討する

**design 側で回答済みの 2 件**（再確認不要）:

3. 識別色を背景にしたときのコントラスト → **満たせない。だから背景に使わない設計にした。**
   通常表現は識別色を 6px の帯にとどめ面は `surface` 固定 / 縮小表現は文字を描かない。
   実測: `#f59e0b` on ライト背景 `#f5f6f8` = **約 2.0:1**、しかも色によって白文字と黒文字が逆転する。
   [ui-spec 15-4](../../design/ui-specs/2026-08-04-character-relationship-graph.md#15-4-開放質問-3-への回答識別色を背景に使ったときのコントラスト)
4. 既存プリミティブの充足 → **`SegmentedControl` の 1 つだけ足りない。**
   [ui-spec 1 章](../../design/ui-specs/2026-08-04-character-relationship-graph.md#1-既存プリミティブの再利用可否先に確認)

**⑥ ライトモード限定の落とし穴（実装前に読むこと）**

ライトモードは階調が狭く、そのまま組むと**見えない要素が 3 つ**できる。UI 仕様はこれを避けるために
トークンを選んでいるので、変えないこと（[ui-spec 15-5](../../design/ui-specs/2026-08-04-character-relationship-graph.md#15-5-実装時の落とし穴ライトモード限定)）。

| やってはいけないこと | 実測 | UI 仕様での回避策 |
| --- | --- | --- |
| `text-muted` を `bg-surface2` の上に置く | **約 4.2:1**（AA 未達。`bg-surface` の白なら 4.83:1 で通る） | 「立ち位置」「ヒント文」は必ず `bg-surface` の上に置く |
| `border-line` を `bg-bg` の上に引く | **約 1.05:1**（事実上見えない） | グループ枠と縮小表現ノードの輪郭は **`border-muted`**（4.4:1） |
| キャンバス背景を無地にする | ノード（`surface` = `#ffffff`）と背景（`bg` = `#f5f6f8`）が **1.06:1** でノードが浮かない | **ドットグリッド**を敷き、不透明なノードがドットを隠すことで「面」を作る（参照ビジュアルの「無地のダーク背景」からの意図的な逸脱） |

**⑦ 実装後にデザインレビューを起票すること**

デザイン部は「動いているものを見て判断する」。実装が終わったら
**ライト / ダーク両方**と **375px / PC 両方**のスクリーンショットを添えてレビューを依頼する。
とくに見るのは:

- ライトモードでノードが背景から浮いているか（ドットグリッドが効いているか）
- 全体表示でグループラベルが読めるか（ズームに追従していないか）
- 縮小表現ノードの `muted` 輪郭が、`CHARACTER_COLORS` 10 色すべてで背景と分離できているか
- ノードアクションバーが図を隠しすぎていないか（選択したノードがバーに隠れていないか）
