## 背景

これは [.claude/CLAUDE.md](../../../CLAUDE.md) と [.company/CLAUDE.md](../../CLAUDE.md) が前提に
している「サーバ無し・データは IndexedDB のみ」を覆す変更であり、プロダクトの土台が変わる。

### 差分 1: スマホは「対応」ではなく「メイン想定」（上書き・確定）

| 項目 | 旧（初回決裁） | 新（2026-08-04 上書き） |
| --- | --- | --- |
| スマホ表示 | 縦リストに切り替え（PC カンバンが主・スマホは代替） | **モバイルファースト**。スマホが主・PC カンバンが副 |
| 設計の判断基準 | PC 基準で設計し、狭い画面はフォールバック | **PC とスマホで仕様が競合したらスマホを優先する** |

- **理由**: メイン利用形態がスマホなら、縦リストは「小さい画面向けの劣化版」ではなく
  「基準となる表示」になる。設計の起点が逆転するため design / dev の前提を書き換える必要がある。
- **波及 (a)**: `オフライン利用` の重要度が上がる（スマホは電波の無い場所で使われる）。
  ただし「移行完了後に再検討」という結論自体は変えない。planning spec に
  **保留のままにする理由を 1 行残す**こと。
- **波及 (b)**: サーバ移行後のログイン画面を含む全画面もスマホ幅 (375px) が基準になる。
  `dev/accounts-and-server-impl` の完了条件に反映済み。
- **波及 (c)**: 画像取り込みがカメラロール経由になる想定。画像サイズ上限（Blob 無料枠）の
  決定は planning spec のスコープ内で扱う。

#### 提示した選択肢と選定結果（履歴として保持）

| 解釈 | 内容 | 結果 |
| --- | --- | --- |
| (a) | バックアップ手段としての JSON 書き出し機能**そのものを廃止** | 不採用 |
| (b) | **DB が正本になるので JSON をバックアップの主手段にするのをやめる**（移行用途では残す） | **採用（社長回答 2026-08-04）** |
| (c) | 移行も JSON 経由をやめる（IndexedDB からサーバへ直接引き取る等） | 不採用 |

（秘書が提示していた既定案も (b) だったが、上記は既定値の自動適用ではなく社長の明示回答）

#### (b) 確定による帰結（後続チケットへの拘束事項）

1. **移行経路としての JSON 読み込みは残す** — 初回決裁の「既存の書き出し/読み込みを再利用し、
   専用の移行 UI は作らない」方針が有効。`parseProjectJson` / `withFreshIds` は削除しない。
2. **バックアップの主手段としての位置づけは廃止** — DB が正本。README・UI 上で
   「JSON で手元に保存してください」と促す導線は落とす。
3. **書き出し UI を「いつ落とすか」は planning spec で具体化する** — (b) は「主手段から外す」で
   あって「即時削除」ではない。**移行が完了する前に消さないこと**（消すと既存作品を DB へ
   持ち込む手段が失われ、復旧不能）。
4. **(c) は不採用** — IndexedDB からサーバへの直接移行導線は作らない。
   `dev/accounts-and-server-data-migration` の設計はこの分岐を畳んで JSON 経由に一本化済み。

#### 影響範囲（実測）

JSON 書き出し/読み込みの呼び出しは 3 箇所のみ。

- `src/app/page.tsx`: 読み込み（`parseProjectJson` / `withFreshIds`）＋ 書き出し
- `src/app/projects/[projectId]/page.tsx`: 書き出し
- 実体は [src/lib/io.ts](../../../../src/lib/io.ts)（`EXPORT_FORMAT = "storyline.project"`）
