タスクを完了処理してください。

引数: $ARGUMENTS (タスクの説明 or ファイルパス)

## 1. 対象ファイル検索 (優先順位順)

| 優先 | キー | 一致方法 |
| --- | --- | --- |
| ① | ファイルパス完全一致 | `$ARGUMENTS` が `.claude/.company/...` で始まればそのファイル |
| ② | ファイル名 slug 部分一致 | `$ARGUMENTS` を Glob で `.claude/.company/**/*<slug>*.md` 検索 |
| ③ | タイトル含有 | `.claude/.company/**/*.md` を Grep で H1 タイトル (`# `) 検索 |

複数ヒット時は候補をリストアップして社長に確認。1 件なら自動確定。

## 2. ステータス行を「完了」に更新

更新フォーマット (Edit で書換え):

```
- ステータス: **完了**（YYYY-MM-DD {実施主体}）
```

- `YYYY-MM-DD` = 今日 (JST)
- `{実施主体}` = タスクが属する部署名 + 必要に応じて補足 (例: 「開発部・親オーケストレータ直接実施」)
- 既存の `- ステータス:` 行を **置換**。ファイル末尾への追記は不可

## 3. 引き継ぎ元の双方向ポインタ更新

タスクファイル冒頭に `← 引き継ぎ元: {元パス}` があれば、その元ファイルを開いて以下を実行:

- `## 引き継ぎ` セクション内の `→ 引き継ぎ先: {このファイル}` 行を:
  ```
  → 引き継ぎ先: {このファイル} ✓ 完了 YYYY-MM-DD
  ```
  に書き換え
- 元ファイル自体のステータスは変更しない (元タスクはそれ単体で完了判定すべきだから)

## 4. 今日の TODO ファイル更新

`.claude/.company/secretary/todos/YYYY-MM-DD.md` (今日) が存在すれば、該当タスク行を **取り消し線** 化:

- 例 (依存テーブル内):
  ```
  | dev | scene-drop-jumps-to-column-end | ~~進行中~~ → ✓ 完了 | — |
  ```
- 行を削除はせず取り消し線で履歴を残す (ブリーフィング再生成時に自動掃除される)

## 5. 次部署起票の必要判定

完了したタスクの `## 引き継ぎ` セクションを確認:

| 状況 | アクション |
| --- | --- |
| `→ 引き継ぎ先:` がある + 先方タスクが既に起票済み | アクション不要 (先方は独立に動く) |
| `→ 引き継ぎ先:` がある + 先方タスクが未起票 | [/handoff](../handoff/SKILL.md) の起票が必要。社長に「{先方部署} へ引き継ぎ起票しますか?」と確認 |
| `→ 引き継ぎ先:` が無い | アクション不要 |

## 6. 完了報告

社長に Markdown で報告:

```
✅ 完了処理完了

- タスク: {タスクタイトル} ([相対パス])
- 完了日: YYYY-MM-DD
- 引き継ぎ元更新: あり/なし
- TODO 更新: あり/なし
- 次部署起票: 不要 / 推奨 (先方: {部署})
```
