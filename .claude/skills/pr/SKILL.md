広報部にタスクを直接指示します。

prサブエージェントを起動し、以下の指示を実行させてください:
$ARGUMENTS

## 起動条件

- 人に説明する文書 (README / 紹介文 / リリースノート) の作成・改善
- 機能追加時の変更まとめ
- 画面素材 (スクリーンショット) の構成指示

## メッセージング (agent 定義より・厳守)

- **コアメッセージ**: 「話の順番と、誰が出てくるかを一望する」
- **書かない**: 「AI が」「自動生成」— この製品に AI 機能は無い (事実に反する)
- **書かない**: 「クラウド保存」「同期」「共同編集」— サーバを持たない
- **必ず明記する制約**: データはブラウザ内 (IndexedDB) にのみ保存され、サイトデータを消すと
  作品も消える。移行・バックアップは JSON の書き出し / 読み込み

## 典型的な依頼パターン

| 種類 | 例 |
| --- | --- |
| README 改善 | 「使い方セクションを追加して初見でも触れるようにする」 |
| 紹介文 | 「共有用の 3 文の説明を 3 案」 |
| リリースノート | 「キャラクター管理の変更点をユーザ視点でまとめる」 |
| 画面素材の構成 | 「機能を伝えるのに必要なスクショ 3 枚の構成と撮影条件」 |

## 事実確認のルール

書く前に必ず裏を取る。確認先の優先順:

1. [README.md](../../../README.md)
2. 該当コード (`src/` 配下)
3. 開発部への確認チケット

推測で機能を書かない。書けない部分は「未確認」と明示して残す。

## 出力先

| 種類 | 保存先 |
| --- | --- |
| 紹介文・リリースノート | `.claude/.company/pr/content/` |
| 画面素材の構成 | `.claude/.company/pr/assets/` |
| 反応・記録 | `.claude/.company/pr/analytics/` |
| 通常タスク | `.claude/.company/pr/tasks/` |

README 自体の書き換えは、ドラフトを `pr/content/` に置いてから
[README.md](../../../README.md) へ反映する。

## モデル選定

引数または対応チケットに明示モデル指定 (haiku/sonnet/opus) があれば Agent の `model` override として渡す。
無ければ [pr](../../agents/pr.md) 既定 (`sonnet`)。難度ルーブリックは [secretary](../../agents/secretary.md) 参照。

## 行動ルール (agent 定義より)

- 誇張しない。「できないこと」を隠さない (ローカル専用は前提であって弱点ではない)
- 用語は UI と揃える (作品 / ストーリー / シークエンス / シーン / キャラクター)
- 外部発信を伴う作業は社長確認を取る

## 上流・下流引き継ぎ

- 画面素材が必要 → [design](../design/SKILL.md) に構成相談
- 機能の挙動が不明 → [dev](../dev/SKILL.md) に確認依頼
- 「こう説明したいが機能が足りない」→ [plan](../plan/SKILL.md) の inbox に起票

引き継ぎは [/handoff](../handoff/SKILL.md) で双方向ポインタを張る。
