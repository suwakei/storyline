日次ブリーフィングを生成してください。

## 日付ハンドリング (厳守)

- すべて **JST (Asia/Tokyo)** で扱う
- **今日** = システム日付 (`YYYY-MM-DD`)
- **昨日** = 今日 - 1 日
- TODO ファイル名: `.claude/.company/secretary/todos/YYYY-MM-DD.md` (例: `2026-05-28.md`)
- 月跨ぎ・年跨ぎは自然な日付計算で

## 実行手順

### 1. 全部署の `tasks/` を走査

走査対象は**各部署の `tasks/` のみ** (絶対パス)。`tasks/` がステータスの唯一の一次情報。
`specs/` `ui-specs/` `content/` `inbox/` 等は成果物・連絡で走査対象外
([.company/CLAUDE.md](../../.company/CLAUDE.md) 「ディレクトリ構成と一次情報」参照)。

- `.claude/.company/dev/tasks/`
- `.claude/.company/planning/tasks/`
- `.claude/.company/design/tasks/`
- `.claude/.company/pr/tasks/`

### 2. 昨日完了の検出

チケットファイルの先頭メタブロックから:

- パターン: `- ステータス: \*?\*?完了\*?\*?(?:（(\d{4}-\d{2}-\d{2})[^）]*）)?`
- 括弧内日付が **昨日と一致** すれば「昨日完了」として収集
- 括弧内日付が無い場合はファイルの最終更新日 (mtime → JST 日付) で代用
- 部署別にグルーピング

### 3. 今日の TODO (未着手 + 進行中)

- パターン: `- ステータス: \*?\*?(未着手|進行中|レビュー中)\*?\*?`
- 優先度行: `- 優先度: \*?\*?(高|中|低)\*?\*?`
- 部署別 → 優先度 高→中→低 で並べる
- 前提依存があれば `- 前提: ...` を併記 (ブロッカー判定の材料)

### 4. ブロッカー検出

次のいずれかに該当するタスクをブロッカーとして警告:
- `## 引き継ぎ` セクションに「→ 引き継ぎ先: X」があり、X 側に対応タスクが存在しない (未起票引き継ぎ)
- `- 前提: ` が「なし」以外で、その前提タスクが未完了
- 5 日以上「進行中」のままステータス更新が無いタスク

### 5. TODO ファイルの作成/更新

`.claude/.company/secretary/todos/{今日}.md` を作成。既存なら追記でなく**再生成** (常に最新スナップショット)。
依存テーブル `| 部署 | チケット | ステータス | 前提/依存 |` を必ず含める。

## 空日時の挙動

- 昨日完了 0 件 → 「### ✅ 昨日の完了\n\n_該当なし_」
- 今日 TODO 0 件 → 「### 📌 今日の TODO\n\n_全部署アイドル。何をしましょう？_」
- ブロッカー 0 件 → 「### 🚧 ブロッカー\n\n_なし_」(セクション自体は残す)

## 出力フォーマット

```
## 📋 {今日の日付 YYYY-MM-DD} ブリーフィング

### ✅ 昨日の完了 (YYYY-MM-DD)
- [{部署}] {タスク名} ([相対パス])

### 📌 今日の TODO
- [{部署}] {タスク名} (優先度: {高/中/低}, ステータス: {進行中/未着手/レビュー中}) ([相対パス])

### 🚧 ブロッカー
- [{部署}] {タスク名}: {ブロッカー理由} (例: 引き継ぎ待ち / 前提未完了 / N 日停滞)
```
