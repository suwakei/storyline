週次振り返りを生成してください。

## 期間定義 (厳守)

- すべて **JST (Asia/Tokyo)**
- 「過去 7 日」 = **本日含む 7 日間** (例: 2026-05-28 実行なら 2026-05-22 〜 2026-05-28)
- 月跨ぎ・年跨ぎは自然な日付計算で

## 実行手順

### 1. 完了タスク収集

[briefing](../briefing/SKILL.md) と同じく**各部署の `tasks/` のみ**を走査:
- `.claude/.company/{dev,planning,design,pr}/tasks/`

`tasks/` がステータスの唯一の一次情報。成果物 (`specs/` `ui-specs/` `content/` 等) と
連絡 (`inbox/`) は走査対象外 ([.company/CLAUDE.md](../../.company/CLAUDE.md) 参照)。

ステータス: `- ステータス: \*?\*?完了\*?\*?(?:（(\d{4}-\d{2}-\d{2})[^）]*）)?`
括弧内日付が **期間内** ならカウント。日付が無いものは mtime (JST 日付) で代用。

### 2. 部署別成果サマリ

完了タスクを部署別にグルーピング。各タスクの 1 行サマリ (ファイル冒頭の H1 タイトル) と相対パスを記載。

### 3. 持ち越し検出

完了以外 (未着手 / 進行中 / レビュー中) のチケットのうち、**期間開始日より前に起票されたもの**を「持ち越し」として収集。
`- 起票日: YYYY-MM-DD` 行で判定。

### 4. ボトルネック検出

以下のいずれかに該当するタスクをボトルネックとして指摘:

| パターン | 検出ロジック |
| --- | --- |
| 長期停滞 | 同一タスクが本期間中ずっと「進行中」(完了せず、起票日 7 日以上前) |
| 引き継ぎ滞留 | `## 引き継ぎ` 「→ 引き継ぎ先: X」があるが X 側未起票・未着手のまま |
| 依存待ち連鎖 | `- 前提: Y` の Y が未完了で、本タスクも 7 日以上未着手 |

### 5. 持ち越し理由の分類タグ

各持ち越しに次のいずれかを付与 (チケット本文から推定):

- `[ブロック待ち]` — 他部署の引き継ぎ完了待ち / 社長手番待ち / 外部依存
- `[規模超過]` — 当初見積もりより大きく、分割が必要
- `[優先度低]` — 着手しなくても運用に影響しない (棚上げ妥当)

### 6. 改善提案

ボトルネックと持ち越し傾向から、来週の動きを 1-3 件提案 (例: 「dev → design レビュー往復が 3 回続いている → 仕様確定の段階で design レビューを挟む手順に変更」)。

### 7. 保存先

`.claude/.company/secretary/notes/YYYY-MM-DD-retro.md` (実行日を YYYY-MM-DD に)。既存なら上書き。

## 出力フォーマット

```
## 🔄 週次振り返り ({期間開始 YYYY-MM-DD} 〜 {期間終了 YYYY-MM-DD})

### 今週の成果
合計 N 件完了。

#### 開発部 (N 件)
- {完了タスク 1 行サマリ} ([相対パス])

#### 企画部 (N 件)
- ...
（以下、デザイン / 広報 の順）

### 持ち越し (N 件)
- [{部署}] [{ブロック待ち|規模超過|優先度低}] {タスク名} ([相対パス])

### 🐢 ボトルネック
- {検出パターン}: {対象タスク} ({根拠})

### 💡 改善提案
- {提案 1}
- {提案 2}
```
